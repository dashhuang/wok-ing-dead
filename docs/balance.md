# 数值怎么调：工具、流程和计划

套餐（肉鸽关卡）的战斗节奏、敌人安排和各种数值，靠三层工具来算、来模拟、来防止改坏。
当前只调**微辣**：中辣和变态辣在菜单上是锁着的，以后作为新关卡再开（`src/settings.js` 的 `openDifficulties`）。

- 现状的全部数字：[balance-report.md](balance-report.md)（生成文件）。
- 数值本身：`src/chinatown/runtune.js`（关卡）、`zombietune.js`（僵尸）、`loadout.js`（弹药）、`arsenal/src/data/`（武器、等级、状态）。
- 规则：`src/chinatown/runflow.js`。时间线、刷什么、击杀给多少镬气、掉什么弹药这些**纯规则**在这里，
  游戏（`run.js`）和模拟器用的是同一份代码，所以模拟的和实际玩的不会是两套规则。

## 三层工具

| 层 | 是什么 | 多快 | 入口 |
| --- | --- | --- | --- |
| 1 数值表 | 由规则直接算：每分钟刷多少、涌入多少血量、每把武器的持续输出和击杀时间、一池弹药能打多少 | 即时 | 报告第 2–4 节 |
| 2 整局模拟 | 不开画面，把一局从点主菜打到关底，每种玩家 100 局，固定随机种子 | 每局约 15 毫秒 | 报告第 5 节，`npm run balance:sim` |
| 3 真实代码实测 | 试验场用真正的武器代码对尸群实测（`arsenal/tools/balance.mjs` → `arsenal/scripts/balance.json`）；模拟器拿它校准 | 每把武器 1 分钟 | 报告第 6 节 |

第 2 层是简化模型（`scripts/balance/engine.mjs` 开头写了它省略什么）：没有地图，瞄准是一个命中率，
**玩家水平是假设**（`scripts/balance/run.mjs` 的 `PROFILES`）。所以它能回答「改了之后变难还是变容易、差多少」，
还不能回答「真人通关率是多少」。后者要靠试玩，或者靠还没做的「真游戏里的机器人」来校准这些假设。

## 命令

```sh
npm run balance          # 重新生成 docs/balance-report.md
npm run balance:check    # 护栏 + 报告是否最新（npm run check 里已经包含）
npm run balance:sim 500  # 只跑整局模拟，每种玩家 500 局，打印到终端
node scripts/balance/lab.mjs                 # 只看模型和实测的对照
node scripts/balance/report.mjs --print      # 报告打印到终端，不写文件
```

## 改数值的流程

1. 改 `runtune.js` 等数值文件（规则要变就改 `runflow.js`，游戏和模拟器一起变）。
2. `npm run balance`，看报告的差异：护栏有没有从「未达标」变成「达标」，别的行有没有被带坏。
3. 把报告和数值一起提交。报告不是最新的话 `npm run check` 会失败，所以 PR 里一定能看到这次改动对数字的影响。
4. 改了武器本身（`arsenal/`）先重新实测：`node arsenal/tools/balance.mjs --write`，再 `npm run balance`。
5. 最后还是要真人玩：模拟看不出手感。试玩结论和报告对不上时，改的是 `PROFILES` 里的玩家假设，不是去凑数值。

## 护栏

目标写成了规则（`scripts/balance/guards.mjs`），列在报告第 1 节。

- **已启用**：现在成立、以后也必须成立，不满足时 `npm run check` 失败。
- **待启用**：计划里要达到、现在还没达到的，只报告。哪次改动达到了，就在那次改动里把它的 `enforce` 改成 `true`。

## 计划

用户定下的四条不动：弹药必须捡、弹药分四种、武器不限数量、红包只升手上那把。

| 步 | 改什么 | 对应的护栏 |
| --- | --- | --- |
| 0 地基（已完成） | 规则抽成 `runflow.js`，三层工具，基线报告；锁上中辣和变态辣 | 已启用的三条 |
| 1a 安静的街（已完成） | 开局游走的行尸；不自动回血，击杀掉外卖盒；换一次弹装满全部；补给箱标记走近才显示 | — |
| 1b 三口灶（已完成第一版） | 警报器换成大排档的灶：主动起灶招来尸群，守到出餐拿奖励，顺序和时机由玩家定 | — |
| 1c 节奏和成长 | 升级减到 10 次左右、第一次推后；行尸和重型随时间变强；修胀尸占比；每道菜的起伏 | 升级的三条、胀尸占比、敌人成长、每道菜有起伏 |
| 2 敌人 | 成群的快尸、厚皮尸；精英各带一个特点 | 专精和全用都走得通 |
| 3 武器和弹药 | 十四把武器按四种弹药重新定位，调输出和掉落 | 武器成长不失控、专精要为弹药奔波 |
| 4 关底 | 分阶段变招，血量用模拟重新定 | 通关率（校准后） |

## 还没做的

- **真游戏里的机器人**：让机器人在真实游戏里打完整局，用来校准 `PROFILES`。在它或足够的试玩数据到位之前，
  报告里的通关率只看相对变化。
- 敏感度分析（每个数值各调 ±20% 看影响）和按目标反推数值，等第 1 步有了要调的旋钮再加。
- 码头分店和手机的尸群规模，模拟器支持（`simulateRun({ place: "docks", device: "phone" })`），报告里还没有单列。
