# 踩过的坑

开发中真的发生过、下次还可能再犯的问题，以及当时的解法。写新代码前扫一眼相关的几条。

## 画面与特效

- **特效亮度要在游戏靶场里看**：游戏夜街的特效乘 `ARMORY_TUNE.fxGain = 0.3`，试验场里看着合适的亮度在游戏里几乎看不见；
  反过来，血的颜色 `BLOOD` 是按夜街定的，在试验场里显得很艳。
- **画面中间一大块黑色方块**：是本体自带的步枪模型画在眼前。开局时游戏会把自带的枪和手臂重新显示，`loadout.js` 的 `stowOwn()`
  每帧保证拿着军械库武器时把它们收起。
- **第一次拿新武器卡一下**：预热时要数“武器图层真的画了”的帧；手上的东西室内、室外各要一套着色器（`render.envWarm`）。
  查法：逐帧比较 `renderer.info.programs` 的 `cacheKey`。
- **雾里的灯光晕要限制范围**：按灯的照射距离给光晕，站在灯附近时每条视线都在范围内，整屏变成一片彩色的雾。现在光晕只有几米大（`streetfx.js` 的 `HALO_FOG`），
  离灯 1 米以内不加。调 `fx.halo` 时到灯下和霓虹密集处各看一眼。
- 无头软件渲染分辨率太低，看不出细小的火星。要用显卡渲染截图，用 Playwright 的 `chromium.launch({ channel: "chromium" })`，
  并注入 `tests/support/fake-pointer-lock.js`，不然系统光标会被锁定拉走。逐帧看特效用 `arsenal/tools/shots.mjs play`，或者 `openLab` 加 `lab.advance`。

- **第一人称的手臂是为画面摆的，不是为人摆的**：为了不让大臂和手肘进画面，肩膀会沉到比手腕低三十多厘米、手肘可以翻到手的上方。
  第一人称里看不出来，一旦把大臂露出来（展柜、陈列馆、将来的第三人称或过场）就是「大臂角度不对」。展柜因此有自己的一套站姿
  （`hands.js` 里所有 `fp ?` 的分支）；改其中一边时用 `arsenal/tools/posture.mjs`（加 `--fp` 量第一人称）确认另一边没动。
- **放样曲面不能沿法线往里收**：车身的圆角原来是把轮廓沿它自己的法线往里偏移，轮廓拐得比偏移量还急的地方（保险杠台阶、机盖前沿）
  偏移线会折回去，曲面自相交，看上去就是转角起皱、保险杠下垂。现在偏移方向取一段轮廓上法线的平均（`vehicles.js` 的 `frame`），
  拐急弯时方向也转得慢，并且会检查偏移线有没有倒着走，有就把取平均的范围加大。车头车尾的弧度同理：只沿前后方向挪，不沿法线挪。
- **车头车尾的侧板不能按竖条铺**：圆角起点那条线在车头车尾几乎是竖着走的，还会前后来回偏，按「每个截面一条竖条」铺会重叠或漏缝。
  这两段现在是按那条线当轮廓剖分出来的一块面片（`endCap`）。
- **贴在车身上的灯和饰条要跟着车身网格走**：按固定间距取点的贴片会从转角的圆弧里面直穿过去，被车身盖住一截。`endPatch` 的列
  现在落在车身网格的行上。
- **半透明玻璃的反射会跟着透明度一起变淡**：普通透明混合把整块颜色乘上不透明度，反射也被乘掉。车窗用金属度 1（只有反射、没有底色）
  加自定义混合（源 `One`、目标 `OneMinusSrcAlpha`）：反射原样加上去，后面的东西按不透明度压暗。不用 transmission。
- **碰撞盒比车身短，镜头就会切进车里**：车的碰撞是沿车长排的一串方盒（`vehicles.js` 的 `footprint`），原来两头各短一截，
  人贴到车角时近裁剪面把车皮切掉，看到车里没封口的地方。碰撞盒要铺满车长；透过玻璃能看到的车内（门下半截、轮拱）也要有朝里的面。
- **不开浏览器也能看车形**：`node scripts/vehicles/preview.mjs van /tmp/van.png`（软件光栅化，出一张多视角的图；`zebra=1` 看曲面顺不顺）。

## 数值

- `scripts/balance/data.mjs` 把每把武器的 `fire.knock` 当作一个数字读（用来模拟击退距离）。有一次把它改成对象，平衡报告的通关率从 91% 掉到 69%（读出 NaN）。
  所以按距离变化的击退另外起名叫 `shove`。改了数据表后如果平衡报告大幅变化，先怀疑模拟器读错了字段。
- 自动对战里打死玩家的主要是精英和关底的爪击。统计伤害来源时，用 `player:hit` 的 `fromPos` 去对僵尸的 `pos` 对象。
- **量武器要在够得着的距离上量**：旧的实测让僵尸从 40 米外的巷子尽头走过来、机器人原地不动，霰弹、喷火器和近战的成绩其实是
  「僵尸走到跟前的速度」，量不出强弱（当时以为镬气和霓虹最弱，换了量法发现它们清群最强）。现在的考法见 `arsenal/tools/balance.mjs`。
  同理，单体别拿 320 血的重型当靶子：最后一击溢出多少会让成绩跳两成，现在用的是精英的血量。
- **实测工具会用 5311 端口上现成的试验场**：别的会话开着试验场时，量到的是它那个工作目录的代码。自己另起一个端口，用 `ARSENAL_URL` 指过去。
- **按最大生命百分比结算的效果要有间隔**：焚符（镇压 + 火，30% 最大生命，关底 4%）原来没有间隔，火符每张符都能触发一次，
  5 级对精英每秒 800 伤害。加新的百分比伤害时先想清楚一秒能触发几次。
- **会叠加的持续伤害区域**：每次命中都生成一个火环 / 电场的武器，射速一高就是十几个区域叠在一处。现在 `ctx.zone()` 会返回这个区域，
  武器可以给已有的续时间而不是再放一个（敕令·火符这样做）。
- 清群那一项重复量有一成以内的浮动，不要为了 0.1 分的差别来回调；贴着目标带边缘的形态先调开一点。

## 手机内存

- **iPhone Safari 的「“网址”重复出现问题」= 页面被系统连续杀掉**，几乎都是内存超限，不是服务器出错。第一次被杀后 Safari 自动重载，
  再被杀就显示这句话。开机保护（`src/bootguard.js`）只能把高于 `low` 的画质退回自动档，本来就在 `low` 时没有退路。
- **查是哪个进程、为什么被杀**：手机连着 Mac 时，`xcrun devicectl device info files --device <UDID> --domain-type systemCrashLogs`
  列出 `JetsamEvent-*.ips`，拷下来看 `reason` 为 `per-process-limit` 的进程和它的页数。2026-11-13 是 `com.apple.WebKit.WebContent`，2049 MB。
- **iPhone 把 WebGL 的显存也算在网页进程头上**：Mac 上图形进程单独占几 GB，iPhone 上图形进程只有几百 MB、网页进程 2 GB。
  所以省显存和省 JS 里的副本同样有效。three.js 上传贴图后默认还留着原图（解码图片、画布），手持设备上由 `texmem.js` 释放；
  新做的画布贴图画完以后不再改，就 `markStatic(tex)`；会在游戏中继续画的（贴花、屏幕）不要标。
- **武器库的模型开机就全部建好**：所有武器、所有岔路的画布都会上传，不管带没带（例如符纸 30 张、关刀龙纹 4 张）。手机档用 `createKit({ canvasScale: 0.5 })`；
  画布里的绘制不要用 `setTransform`（会冲掉这个缩放），用 `save` / `transform` / `restore`。
- 本机量内存：Playwright 的 WebKit（`npx playwright install webkit`）带 iPhone UA 打开，`vmmap -summary <WebContent pid>` 看
  `CG Raster Data`（画布）、`Untagged (graphics)`（解码图片）、`WebKit Malloc`、`JS VM Reservations`。手机经局域网打开
  `vite preview --host` 的构建即可实测，不用部署。起服务前先 `lsof -iTCP:<端口>`，别的会话常占着 5185–5187。
- **在 iPhone 上找帧率瓶颈**：先用固定机位（`?autostart=1&noaudio=1&dynres=0`），不要用跑分路线比较配置：
  镜头在走，前后两次读数看到的东西不同，同一配置能差出几倍。手机连续跑几分钟会发热降频，配置要交替测几轮。
  计数脚本做法：本机 `npm run build` 后往 `dist/index.html` 的 `<head>` 里插一个只在 `?prof=1` 时生效的脚本，
  包一层 `requestAnimationFrame`、`renderer.render` 和 WebGL 的 draw / uniform / useProgram，在屏幕上显示每帧次数和耗时，
  手机经局域网打开即可读数（不用 Web Inspector）。Safari 上 `renderer.render` 的 CPU 时间约等于调用次数 × 每次 40～100 µs。
- **长音频不要整首 `decodeAudioData`**：解码后是 32 位浮点 PCM，48 kHz 立体声每分钟约 22 MB。两首配乐（共约 4 分 49 秒）
  解码后约 110 MB，是 MP3 的十几倍。配乐、环境长音轨用 `<audio>` 加 `createMediaElementSource` 边播边解；短音效才解码成 buffer。

## 测试（现在暂停，再用时注意）

- **预览 / 浏览器验证时不要重建同一个 `dist`**：Vite 构建会清空旧的带 hash 模块，已打开的页面稍后动态导入僵尸或武器时就返回 404，游戏可能降级启动，让开局小票等待超时。先完成构建，再启动验证；必须同时构建时使用独立工作目录或独立输出目录。PR #42 的 trace 已遇到这个问题，不能当成玩法回归，也不能把失败记为测试通过。

- 这台 Mac 忙的时候，无头浏览器每秒不到 1 帧：依赖“游戏内时间”的等待会拖成几分钟。测试里不要等游戏时间推进，靶场补位用现实时间。
- 改窗口尺寸后页面会停顿十几秒，紧跟着的点击要给足等待。新测试尽量共用一次页面加载，慢的测试单独 `test.setTimeout`。
- 同一个工作目录里不要同时跑 `npm run arsenal:test` 和 `npm run test:e2e`：它们共用 `test-results/`，会互相清掉临时文件，造成假失败。
- 端口被别的会话占着时（“is already used”），用 `E2E_PORT` / `ARSENAL_E2E_PORT` 换一个端口。
- Chromium 在 macOS 上真的锁定鼠标会移动系统光标，见 AGENTS.md。

## 仓库与流程

- 好几个会话同时往 `main` 推，推送前先 fetch，必要时 rebase。
- **叠放的 PR**：squash 合并底下的 PR、再删它的分支，GitHub 会把叠在上面的 PR 直接关掉。先把上面的 PR 改成指向 `main`，再合并底下的。
  合并前看一眼有没有别的 PR 叠在它上面，并提前告诉 Dash。
- 仓库是免费版私有仓库：分支保护和规则集的接口永远返回 403（Upgrade to GitHub Pro），`main` 没有强制保护。这一点不用处理。
- Cindy 定时任务的前置检查脚本默认落在主目录的 `scripts/schedule-checks/`，要用 `workingDir` 指到自己的 worktree。
