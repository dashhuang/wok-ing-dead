# 用户定下的方向与偏好

Dash 对这个游戏拍过板的事，按主题列出，带日期；引号里是原话（语音输入的已按原意纠错）。
这些是硬约束：改相关内容前先看这里，想推翻其中一条要先问 Dash。新的决定也记在这里，不要只记在聊天或个人记忆里。

## 总体

- 「要以 3A 游戏的品质来要求」；「摆脱原本游戏的复制感」。名字「还是叫 wok-ing-dead 之类的好玩」→《行尸走镬 Wok-ing Dead》。（2026-11-11）
- 菜单「和最早的原版还是太像了，可以针对我们游戏自己的特色和风格优化」→ 唐人街炒锅餐馆主题，菜单用厨房双关；HUD 和无线电台词保持严肃。（2026-11-12）

## 美术与界面

- **外部美术素材**：风格不统一、品质看起来不够 3A 的不要。但不要一刀切：SUBLEVEL 07 是认可保留的案例（湿地反射、锈蚀金属、地下设施可研究），
  它附带的实验仍要逐项挑。收素材先看实机是否风格一致、有 3A 观感，不因为热门、数量多或能下载就收。（2026-11-12）
- **UI 适度漫画化**：手机战斗按钮用图标，四种弹药用简单线条图标。首版被嫌「不好看、过于复杂，尤其换弹和跳跃」：
  操作图标用一眼能认出的单一符号，少叠组合元素，边框和阴影克制；弹药数量保留数字，名称保留本地化的无障碍标签。
  不要把菜单、剧情、武器名等文字也都删掉。（2026-11-13）
- **对白不要打字机效果**：逐字出现看不清，尤其战斗中。对白整句显示，优先保证对比度、字号和阅读时间。
  漫画风格是 Dash 提的探索方向，不代表所有界面都要改成漫画或卡通。（2026-11-13）

- **补给点提示与普通掉落统一**：「我想补给点的规则和普通掉落一样，不用单独做提示了」→ 去掉补给箱的发现与 HUD 导航标记，领取共用普通弹药提示，保留箱子灯光。（2026-11-13）

## 玩法：套餐（肉鸽关卡）

- 「改成简单一点的 roguelike，体验爽快为主，但升级选择也不要过多打断游戏节奏」，参照吸血鬼幸存者这类关卡制；它取代了原来的套餐。（2026-11-12）
- **四条不要动**：弹药必须捡（要走位、要搜索）、弹药分四种、武器不限数量、红包只升手上那把——主力升一把还是每把都用，是留给玩家的抉择。
- **被否决、不要再提**：备弹无限；杀敌给收着的枪回弹；选小票的 9 秒倒计时。（2026-11-12）
- 选小票：街上放慢到 0.05 倍、玩家停手、鼠标松开可以点、不限时。（2026-11-12）
- 换枪：按弹药分组的数字键被否决。现在是 1–9 按捡到的顺序（1 是手枪）、滚轮依次切换、轻按 Q 回上一把、
  按住 Q / 手柄 Y / 触屏长按开武器轮盘（0.15 倍慢动作，鼠标方向选，松开换上）。（2026-11-12）
- **移除港区地图**：「去掉我们游戏的港区地图」→ 只保留金龙街，删除分店入口、港区解锁和专用台词，旧的 `?lvl=harbor` 链接进入唐人街。
  补充：「我希望能够保留这个的场景代码，作为参考」→ 原始发布包保留在 `upstream/artifact.html`，港区可读场景快照保留在 `references/saltline-harbor/`，不恢复游戏入口。（2026-11-13）

## 陈列馆与靶场

- 「把陈列馆和靶场整理一下，放进游戏里，首页可以有入口」（2026-11-13）。陈列馆指 `arsenal/` 的展柜，靶场是 `/?range=1`。
  做法（Cindy 定的，Dash 还没看过）：两者都是游戏的房间，各是一个页面——陈列馆随站点一起构建到 `/gallery/`，
  首页顶栏有「家伙陈列」「试菜靶场」两个入口，两边能互相跳、都能回首页。入口的名字是按菜单的厨房双关起的，Dash 没定过。

## 武器与打击感

- 武器在独立的试验场（`arsenal/`）先做、单独验证，再接进本体（2026-11-11）；之后「把他做成完全统一，所有改动两边同时有效，方便调试」，
  「靶场直接用游戏的场景」→ 规则和数值只有一份，靶场在游戏里（`/?range=1`）。（2026-11-12）
- Dash 很在意手和手臂是否自然，会在展柜里转着看：托枪的手要斜托（手指与枪管成 50–55°、拇指顺枪管），手腕基本是直的。
- 在陈列馆里看到「这些手臂大臂的角度都有问题，通病」（2026-11-13）：大臂斜着往下插、手肘翻到手上面。
  → 陈列馆（展柜）里手臂按真人的站姿摆：肩膀不下沉、手肘朝下略朝外、大臂从肘往上回到肩。第一人称仍然用它自己那套
  （肩膀下沉、手肘躲出画面），因为那里看不到大臂；两处不是同一套摆法是有意的。
- 后坐力和音效要所有武器一起达到 3A 观感（2026-11-13）。手感和声音要 Dash 上手、试听后才算确认，测量和自动测试不能代替。
- **取消开镜**：现有武器全部不开镜，开镜没有值得保留的玩法意义。右键只给有副攻击的武器分支；手机上是按住使用、松开结束。
  UI 不要画准星式的瞄准按钮。将来有真正有意义的狙击枪机制时再考虑。（2026-11-13）
- 受击要更明显（像暴血）；特别的武器要有击退，霰弹近距离更明显；体型小的敌人死亡时被打飞。（2026-11-13）
  随后：「飞得距离和血的多少要有随机性、和数值有点相关，不要都那么多那么远」。（2026-11-13）
- 「希望能做出敌人断肢的血腥效果」。（2026-11-13）
- 礼花：近看要经得起细看、散落要自然；世界尺寸远近一样但要更大（近看夸张）；像普通爆炸一样会误伤自己。（2026-11-13）
- **数值统一**：「我们要再统一整理一下游戏的数值，特别是各种枪械的平衡」（2026-11-13）→ 武器的每个形态对同一条标准线，
  见 [balance.md](balance.md)「武器的统一标准」。随后：「卡宾枪和手枪也要放进去一次测试，标准一样」（2026-11-13）→ LK-9、LK-4 也考同样两场、
  对同样的目标带。标准线、目标带、「一池弹药对每把枪值同样多」「不用弹药的武器不高过吃弹药的」「没有岔路的武器升级更陡」
  是照这两句话做出来的方案，Dash 还没有上手确认；他试玩后有不同意见就按他的改，并把结论记在这里。

## 开发流程

- 小改动可以直接推 `main`，大改动走 PR。（2026-11-12）
- **AI 发的 PR，检查没问题就自己合并**：「以后我们这个项目的 PR，你发出来以后检查没问题就自己合并」（2026-11-12）。
  条件：CI 全绿、没有未解决的评审线程、可以干净合并、head 没变；用 Squash and merge，合并后确认生产部署。
  检查失败、或者有需要 Dash 拍板的产品问题时不要合并。别人发的 PR 仍要 Dash 授权。
- **小问题修完不用留自动测试**：「这类问题，以后感觉不需要留测试」（2026-11-13，修弩箭不在准星中心时说的）。
  瞄准偏移、特效、手感、数值微调这类修复不新增长期保留的测试，也不在文档里登记测试；已有的测试不删。
  新玩法、规则、流程这类大改动要不要留测试没有定，拿不准时问一句。
- **CI 与测试**：
  - 「现阶段这类测试不太有必要」→ 冒烟测试改按需。（2026-11-12）
  - 「简化一下我们的 CI，不需要复杂的检查，最简单就好」→ 去掉了自托管 runner、Dependabot、冒烟测试工作流。（2026-11-13）
  - 「这类保护可以加上。只是不需要跑游戏测试了，暂时」→ 推送前钩子和 CI 跑 `npm run check`，CI 再构建。（2026-11-13）
  - 「本地的冒烟测试也简单一点，暂时不需要跑游戏」→ 本机验证是 `npm run verify`，暂时不在浏览器里跑游戏。（2026-11-13）
- **项目知识写进仓库**：「我们跟游戏相关的信息一定都要落到游戏仓库中，而不要落到我们这个项目的记忆里面」。（2026-11-13）
  决定记在本文件，现状和待验证记在 [status.md](status.md)，踩过的坑记在 [pitfalls.md](pitfalls.md)。
