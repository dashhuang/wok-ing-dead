# 鬼市 Ghost Market 架构与代码导航

## 先看什么

这是一个纯浏览器的第一人称射击游戏，用 Vite 提供开发服务和构建，没有后端，也没有 UI 框架；界面由 DOM、模板字符串和 CSS 构成。

代码分两部分：

- `src/game.js`：原版发布包。Three.js r180 和整套游戏（渲染、材质、物理、武器、输入、HUD、任务）都在同一个闭包里，
  变量名是压缩后的。搜索函数声明或 `// ===` 分区标记来定位，不要依赖行号。
- `src/chinatown/`：唐人街版本新增的普通 ES 模块，负责关卡、远景、僵尸和音频，通过游戏上下文对象与原版系统对接。
- `src/i18n/`：界面语言与界面字体。`game.js` 以 `L10N` 的名字导入它，HUD、菜单、无线电、加载提示里的所有文字都经由它取得。

推荐阅读顺序：`src/main.js` → `cL`（装配）→ `src/chinatown/level.js`（场景怎么搭）→ `pT`（玩法）→
`src/chinatown/zombies.js` → `xE` / `I5`（玩家、武器）→ `ov`（渲染）。

## 两部分怎么接在一起

- **同一个引擎实例**：`cL` 把内嵌的 THREE 命名空间发布到 `globalThis.__SALTLINE_THREE__`，`src/engine/three.js` 再把它按名字导出；
  `vite.config.js` 把 `three` 指向这个文件。因此 `three/examples` 里的 GLTFLoader、SkeletonUtils 以及新模块里的
  `import * as THREE from "three"` 用的都是游戏自己的那份引擎（package.json 里的 `three` 只为这些附加组件提供源码）。
- **上下文对象**：`cL` 创建的 `t`（调试时为 `window.__G`）含 THREE、参数、事件总线、随机数、时间、画质和 `util.mergeStatic`，
  各系统创建后挂回上面。新模块只通过它访问 `scene`、`mats`、`physics`、`props`、`events`、`player`、`camera`、`fx`。
- **世界参数**：`game.js` 里的 `CT` 对象集中了唐人街与港口在全局层面的差异——取消海面、扩大导航网格、黄昏天光、
  地面积水点位、路面标线的绘制、沥青着色器的改写。`CT.apply()` 在任何系统创建之前执行；`?lvl=harbor` 时不执行，原版关卡照常工作。
- **材质**：`mats.adopt(material, { wet, macro, interior })` 把任意 `MeshStandardMaterial` 接进原版的雨水着色片段
  （淋湿变暗、垂直面水痕、室内探针），外部 PBR 贴图和 GLB 道具因此与原版表面一致。
- **替换点**：`cL` 中 `level`、`backdrop`、`enemies` 三个模块改为动态导入 `src/chinatown/` 下的实现；音频系统在原位置加载
  `src/chinatown/audio.js`。

## 多语言与界面

- **语言包**：`src/i18n/locales/{en,zh-CN,zh-TW,ja}.js`，扁平的键值表。英文是基准，其他语言缺键时回退到英文；
  `{n}` 这样的占位符由 `t(key, vars)` 填入；键名以 `Html` 结尾的值是受信任的标记（只用 `<kbd>`）。
- **选择顺序**：`?lang=` → localStorage `ghostmarket.lang` → 浏览器语言 → 英文。`setLocale()` 设置 `<html lang>` 和
  `data-script`（`latin`/`sc`/`tc`/`jp`），CSS 据此收紧中日文的字距和行高。
- **静态文字**：菜单和 HUD 的标记里用 `data-i18n`（文本）、`data-i18n-html`（标记）、`data-i18n-aria`（无障碍标签），
  切换语言时 `applyDom()` 统一刷新。
- **动态文字**：目标、提示、弹药提示、击杀播报、波次警告在显示时调用 `L10N.t()`；无线电台词 `Vu` 是一组 getter，入队时取当前语言。
  `sT`（HUD）、`hT`（菜单）、`pT`（任务）各自用 `L10N.onLocale()` 在切换后重画罗盘、目标、结算与死亡统计等已显示的内容。
- **字体**：全部通过 `FontFace` 加载（单文件版的 URL 映射依赖这一点）。拉丁界面字体（Inter、Noto Serif Display）总是加载；
  中日文字体只加载当前语言那一份，换语言时替换。中日文语言下拉丁字体用 `unicodeRange` 让出 `· — … “ ”`，这些标点改用全角字形。
  场景贴图用的 Big Shoulders / Barlow Condensed / IBM Plex Mono 也在这里注册。
- **界面结构**：标题页（品牌标志、语言切换、出发/设置/操作、模式与难度、操作速查）、暂停/死亡/结算卡片、右侧设置抽屉
  （设置、操作、关于）都由 `hT` 生成，样式在 `src/style.css` 开头的设计变量里统一定义（墨黑、宣纸白、朱砂、玉绿）。

## 关卡接口

`createLevel(G)` 返回的对象与原版 `Pg` 相同，其他系统依赖这些字段：

| 字段 | 用途 |
| --- | --- |
| `playerStart` | 出生位置和朝向 |
| `objectives[]` | `{ id, label, zone, pos, object }`，`object.userData.setState("live" \| "cutting" \| "cut")` 驱动警报器外观 |
| `extraction` | 撤离点位置与半径 |
| `enemySpawns[]` | `{ pos, zone, type: "ground" }`；创建时会剔除不可走或与出生点不连通的点 |
| `interiorBoxes[]` | 室内范围（街市大厅）：渲染器在此采集室内环境探针，雨、地面湿度、音频混响都据此切换 |
| `cinematicPath[]` | 标题画面和 `?bench=1` 的镜头路径 |
| `explosives[]` | 可引爆的油桶、气瓶，由爆炸物系统生成 |
| `groundSurfaceAt(x, z)`、`update(dt)` | 脚步材质；每帧更新（灯光调度、灯笼摆动、警报器、血泊） |

物理是原版的轴对齐包围盒世界：`physics.addBox` 加碰撞，高度低于 0.47 m 的盒子（路缘、台阶、庙宇月台）不阻挡导航，
`playerOnly` 的盒子挡人和导航但不挡子弹。因此整个街区按正交网格布局，导航网格为 0.5 m 一格。

## 唐人街模块

| 模块 | 做法 |
| --- | --- |
| `kit.js` | 载入 PBR 贴图组和 GLB 道具；提供以米为单位自动展 UV 的盒子、四边形、圆柱、细杆、悬链线；所有静态几何按材质合并成少量网格；纯色表面共用带顶点色的材质 |
| `buildings.js` | 一栋楼是带真实窗洞的薄壳。临街立面按开间生成店面（卷闸、半拉卷闸漏光、玻璃橱窗、住宅门、黑洞门口）、牌匾或灯箱、竖招牌、雨棚、阳台、消防梯；后巷立面是后门、铁窗、水管、空调和污渍。远景用 `simple` 选项省掉窗框 |
| `signs.js` | 四张 Canvas 图集：霓虹/灯箱（自发光）、漆面牌匾与海报（受光）、亮窗与店内景（自发光）、血迹与窗棂（带透明）。图集用天际线装箱 |
| `landmarks.js` | 牌楼、街市大厅（室内）、关帝庙院落、检疫关卡、街口路障、三座警报器、灯笼实例化与摆动；也负责把原版道具（路障、围栏、沙袋等）交给原版的合并函数 |
| `dressing.js` | 宝塔路灯、跨街灯笼串、电线杆与电线、盖着篷布的车、摊位杂物、后巷灯泡串、天井 |
| `backdrop.js` | 四个街口向外延伸的街区、填充街区、远处带亮窗的塔楼、关卡外的军车、堵在西口的车和巴士、盘旋的直升机 |
| `lights.js` | 每个霓虹灯、路灯、橱窗、灯笼串都登记为一个发光体；固定数量的点光源（按画质 4–12 个）按相机距离和朝向分配给最相关的发光体并淡入淡出，着色器里的灯数因此不变。另有随相机移动的枪灯 |
| `zombies.js` | 30 个对象的池；Mixamo 骨骼动画（待机、走、跑、爬、攻击、嘶吼、倒地）；按视线、距离和枪声感知；网格寻路加直线捷径；攻击在动作的实际出手帧结算；头、躯干、四肢分别用球和胶囊做命中检测 |
| `audio.js` | 采样的僵尸语音与脚步、城市环境声、三座警报器的空间循环声 |

新增招牌文字后要重新生成字体子集，新增道具后要更新素材清单，见 [素材来源与许可](assets.md)。

## 初始化顺序

1. 渲染器、场景、世界相机与武器相机。
2. 材质、物理、道具工厂、输入。
3. 关卡 → 远景 → 地面，然后 `physics.build()` 建立导航数据。
4. 特效、音频、玩家、战斗和爆炸物。
5. 武器、僵尸、HUD、任务状态机。
6. `render.onLevelReady()`：采集室内探针并预编译着色器，然后启动动画循环。

启动助手 `r` 捕获模块加载异常；渲染与关卡属于必要模块，其余在有替身实现时可以降级。因此 `__ready` 为真不代表所有系统正常，
仍应检查 `__errors`。局部点光源必须在第 6 步之前全部创建，之后增减灯数会触发全部材质重新编译。

## 每帧如何推进

由 `renderer.setAnimationLoop` 驱动，dt 最大截到 0.05 秒。顺序是：输入 → 游戏状态机 →（允许推进时）玩家、武器、僵尸、爆炸物 →
（非暂停时）特效、地面、关卡、远景、材质 → 音频、HUD → 渲染 → 清理输入的帧内状态。

事件总线用于 `enemy:killed`、`enemy:voice`、`game:state`、`objective:done`、`weapon:fire` 等联动，避免把所有逻辑塞进主循环。

## 玩法与状态

状态为 `title`、`intro`、`playing`、`paused`、`dead`、`complete`。

- Mission：切断三座警报器再抵达检疫关卡。每切一处生成一波尸潮并补充弹药，全部切断后持续有追兵。
- Holdout：持续波次，清场后休整、补给、治疗，再生成下一波。

难度表调整僵尸的生命、伤害、奔跑比例、感知范围和同时存在数量。设置保存在 `saltline.settings.v1`，无尽模式纪录另有存储键。

## 验证入口

- `npm run check`：语法检查和格式检查。
- `npm run build`：Vite 模块解析与生产打包。
- `/?autostart=1&noaudio=1`：启动冒烟检查；核对 `__ready`、`__fatal`、`__errors` 和 `__G.game.state`。
- `__G.game.debugCut()`：直接切断下一座警报器，用来走完整个任务流程。
- `__G.physics.nav._grid()`：导航网格，改动布局后用它检查目标点和撤离点是否连通。
- 实际游玩还需验证瞄准、射击、换弹、暂停、目标推进与声音；构建成功不能替代这些检查。
- 界面改动后用真实点击走一遍：标题页切换语言 → 出发 → Esc 暂停 → 设置里换语言 → 继续 → 死亡重试 → 通关再出发，
  并在桌面、手机竖屏、手机横屏（触屏）三种尺寸下各看一次。
