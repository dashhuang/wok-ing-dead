# 行尸走镬 Wok-ing Dead 架构与代码导航

## 先看什么

这是一个纯浏览器的第一人称射击游戏，用 Vite 提供开发服务和构建，没有后端，也没有 UI 框架；界面由 DOM、模板字符串和 CSS 构成。

代码分两部分：

- `src/game.js`：原版发布包。Three.js r180 和整套游戏（渲染、材质、物理、武器、输入、HUD、任务）都在同一个闭包里，
  变量名是压缩后的。搜索函数声明或 `// ===` 分区标记来定位，不要依赖行号。
- `src/chinatown/`：唐人街版本新增的普通 ES 模块，负责关卡、远景、僵尸、音频和套餐（肉鸽关卡），通过游戏上下文对象与原版系统对接。
- `arsenal/`：十二把肉鸽武器的试验场，可单独运行。游戏通过 `src/chinatown/armory.js` 直接导入其中的武器模型、特效和战斗模块；
  反过来，试验场读本体的三张数值表（`runtune.js`、`loadout.js`、`zombietune.js`）。武器在两边跑的是同一份规则，见下文「试验场和本体共用的规则」。
- `src/i18n/`：界面语言与界面字体。`game.js` 以 `L10N` 的名字导入它，HUD、菜单、无线电、加载提示里的所有文字都经由它取得。

推荐阅读顺序：`src/main.js` → `cL`（装配）→ `src/chinatown/level.js`（场景怎么搭）→ `pT`（状态机）→
`src/chinatown/run.js`（套餐关卡的规则）→ `src/chinatown/loadout.js` / `armory.js`（武器怎么接进来）→
`src/chinatown/zombies.js` → `xE` / `I5`（玩家、武器）→ `ov`（渲染）。

## 两部分怎么接在一起

- **同一个引擎实例**：`cL` 把内嵌的 THREE 命名空间发布到 `globalThis.__SALTLINE_THREE__`，`src/engine/three.js` 再把它按名字导出；
  `vite.config.js` 把 `three` 指向这个文件。因此 `three/examples` 里的 GLTFLoader、SkeletonUtils 以及新模块里的
  `import * as THREE from "three"` 用的都是游戏自己的那份引擎（package.json 里的 `three` 只为这些附加组件提供源码）。
- **上下文对象**：`cL` 创建的 `t`（调试时为 `window.__G`）含 THREE、参数、事件总线、随机数、时间、画质和 `util.mergeStatic`，
  各系统创建后挂回上面。新模块只通过它访问 `scene`、`mats`、`physics`、`props`、`events`、`player`、`camera`、`fx`。
- **世界参数**：`game.js` 里的 `CT` 对象集中了唐人街与港口在全局层面的差异——取消海面、扩大导航网格、黄昏天光、
  地面积水点位、路面标线的绘制、沥青着色器的改写。`CT.apply()` 在任何系统创建之前执行；`?lvl=harbor` 时不执行，原版关卡照常工作。
- **两关**：上下文里的 `stage` 是 `"street"`（金龙街）或 `"docks"`（咸水码头，即 `?lvl=harbor` 的原版港口地图）。一页只载入一关，
  标题页的「分店」按钮改地址后重新载入。码头用的仍是原版关卡代码 `Pg`，只在它返回后、`physics.build()` 之前调用
  `docks.js` 的 `prepareDocks`：放补给箱，并把撤离口通道里那个系缆桩标成不计入导航（人能侧身过，导航网格却把两米宽的通道判成死路，
  僵尸进不去也出不来）。原版关卡的 `enemySpawns` 里还有 `type: "air"` 的点，僵尸和武器箱都只用地面的；
  套餐的规则、僵尸、武器两关共用，差异集中在 `RUN.places`（刷怪倍率、精英间隔、关底血量、拾取物亮度）和带 `@docks`
  后缀的文案（`L10N.setVariant("docks")` 后，`t("radio.intro")` 先找 `radio.intro@docks`）。
- **材质**：`mats.adopt(material, { wet, macro, interior })` 把任意 `MeshStandardMaterial` 接进原版的雨水着色片段
  （淋湿变暗、垂直面水痕、室内探针），外部 PBR 贴图和 GLB 道具因此与原版表面一致。
- **替换点**：`cL` 中 `level`、`backdrop`、`enemies` 三个模块改为动态导入 `src/chinatown/` 下的实现；音频系统在原位置加载
  `src/chinatown/audio.js`。

## 多语言与界面

- **语言包**：`src/i18n/locales/{en,zh-CN,zh-TW,ja}.js`，扁平的键值表。英文是基准，其他语言缺键时回退到英文；
  `{n}` 这样的占位符由 `t(key, vars)` 填入；键名以 `Html` 结尾的值是受信任的标记（只用 `<kbd>`）。
- **选择顺序**：`?lang=` → localStorage `wokingdead.lang`（兼容旧的 `ghostmarket.lang`） → 浏览器语言 → 英文。`setLocale()` 设置 `<html lang>` 和
  `data-script`（`latin`/`sc`/`tc`/`jp`），CSS 据此收紧中日文的字距和行高。
- **静态文字**：菜单和 HUD 的标记里用 `data-i18n`（文本）、`data-i18n-html`（标记）、`data-i18n-aria`（无障碍标签），
  切换语言时 `applyDom()` 统一刷新。
- **动态文字**：目标、提示、弹药提示、击杀播报、波次警告在显示时调用 `L10N.t()`；无线电台词 `Vu` 是一组 getter，入队时取当前语言。
  `sT`（HUD）、`hT`（菜单）、`pT`（任务）各自用 `L10N.onLocale()` 在切换后重画罗盘、目标、结算与死亡统计等已显示的内容。
- **字体**：全部通过 `FontFace` 加载（单文件版的 URL 映射依赖这一点）。拉丁界面字体（Inter、Noto Serif Display）总是加载；
  中日文字体只加载当前语言那一份，换语言时替换。中日文语言下拉丁字体用 `unicodeRange` 让出 `· — … “ ”`，这些标点改用全角字形。
  场景贴图用的 Big Shoulders / Barlow Condensed / IBM Plex Mono 也在这里注册。
- **界面结构**：标题页（品牌标志、语言切换、出发/设置/操作、模式与难度、操作速查）、暂停/死亡/结算卡片、右侧设置抽屉
  （设置、操作、关于）都由 `hT` 生成，样式在 `src/style.css` 开头的设计变量里统一定义（墨黑、宣纸白、朱砂、玉绿）。

## 关卡接口

`createLevel(G)` 返回的对象与原版 `Pg` 相同，其他系统依赖这些字段：

| 字段 | 用途 |
| --- | --- |
| `playerStart` | 出生位置和朝向 |
| `objectives[]` | `{ id, label, zone, pos, object }`，`object.userData.setState("live" \| "cutting" \| "cut")` 驱动警报器外观 |
| `extraction` | 撤离点位置与半径 |
| `enemySpawns[]` | `{ pos, zone, type: "ground" }`；创建时会剔除不可走或与出生点不连通的点 |
| `interiorBoxes[]` | 室内范围（街市大厅）：渲染器在此采集室内环境探针，雨、地面湿度、音频混响都据此切换 |
| `cinematicPath[]` | 标题画面和 `?bench=1` 的镜头路径 |
| `explosives[]` | 可引爆的油桶、气瓶，由爆炸物系统生成 |
| `supplySites[]` | 补给箱：`{ id, pos, yaw, top }`，每关十二处。金龙街的箱子烘进静态街景，码头的是单独的物体；哪八个有货、各是哪种弹药由 `run.js` 每局随机决定 |
| `groundSurfaceAt(x, z)`、`update(dt)` | 脚步材质；每帧更新（灯光调度、灯笼摆动、警报器、血泊） |

物理是原版的轴对齐包围盒世界：`physics.addBox` 加碰撞，高度低于 0.47 m 的盒子（路缘、台阶、庙宇月台）不阻挡导航，
`playerOnly` 的盒子挡人和导航但不挡子弹。因此整个街区按正交网格布局，导航网格为 0.5 m 一格。

## 唐人街模块

| 模块 | 做法 |
| --- | --- |
| `kit.js` | 载入 PBR 贴图组和 GLB 道具；提供以米为单位自动展 UV 的盒子、四边形、圆柱、细杆、悬链线；所有静态几何按材质合并成少量网格；纯色表面共用带顶点色的材质 |
| `buildings.js` | 一栋楼是带真实窗洞的薄壳。临街立面按开间生成店面（卷闸、半拉卷闸、玻璃橱窗、住宅门、黑洞门口）、牌匾或灯箱、竖招牌、阳台、消防梯；橱窗和半拉卷闸后面的房间、店面上的遮阳篷交给 `shopfit.js`；后巷立面是后门、铁窗、水管、空调和污渍。远景用 `simple` 选项省掉窗框 |
| `signs.js` | 四张 Canvas 图集：霓虹/灯箱（自发光）、漆面牌匾与海报（受光）、亮窗（自发光）、血迹与窗棂（带透明）。图集用天际线装箱 |
| `shopfit.js` | 店铺内景与遮阳篷。每个玻璃店面或半拉卷闸后面是一间真实的房间（杂货铺、茶餐厅、药材铺、烧腊店、茶庄），货架、柜台、桌椅、货品都是几何体，用一张 2048 图集上的包装、菜单、字画贴图。房间不占用光源：载入时按房间里的灯位逐顶点烘焙光照（对家具做阴影射线、墙角压暗、街上透进来的冷光），用不受光的顶点色材质绘制。楼房生成时只登记房间，`finish()` 统一规划（街角两家店互相让位、进深不超过楼的一半）后建成，按街区合并；地板墙面单独成网格以便出现在湿路面倒影里。低画质和远景街区用简化版。遮阳篷是带下垂和扇贝边的帆布，中间缝着店名 |
| `market.js` | 街市大厅：砖墙铁皮棚，主过道上方两跨是玻璃天窗（不受光材质，放在倒影图层里，室内环境探针因此能采到天光）。十字过道之间按行当摆档口——冰鲜、活海鲜鱼缸、鲜肉、活禽、鸡蛋、干货、豆腐、蔬菜、水果、粮油、粉面，各有柜台、货品、档口牌、吊灯和帆布顶。货品、招牌、价钱牌、水缸、地面水渍都来自一张 Canvas 图集，经哑光、亮面、自发光、透明四个共用材质绘制，颜色靠顶点色区分，所以整个大厅只有几次绘制调用 |
| `vehicles.js` | 程序化车辆：的士、轿车、掀背车、面包车、小巴、货车、军车、巴士。车身由侧面轮廓放样成曲面，带清漆车漆、半透明车窗、座椅方向盘、车灯、车牌和车身文字；`far` 选项给远景用的省面版本，双闪灯由一个共用材质和发光体同步闪烁 |
| `landmarks.js` | 牌楼（柱脚有抱鼓石）、关帝庙院落（三足鼎香炉、神龛）、检疫关卡、街口的钢板围挡、三座警报器、灯笼实例化与摆动；也负责把原版道具（路障、围栏、沙袋等）交给原版的合并函数 |
| `dressing.js` | 宝塔路灯、跨街灯笼串、电线杆与电线、停在街上的车（多数是 `vehicles.js` 的车，另有两辆盖着篷布）、路口的红绿灯与街名牌、路边雨水口、摊位杂物、后巷灯泡串、天井 |
| `backdrop.js` | 四个街口向外延伸的街区、填充街区、远处带亮窗的塔楼、关卡外的军车、堵在西口的车和巴士、盘旋的直升机 |
| `lights.js` | 每个霓虹灯、路灯、橱窗、灯笼串都登记为一个发光体；固定数量的点光源（按画质 4–12 个）按相机距离和朝向分配给最相关的发光体并淡入淡出，着色器里的灯数因此不变。另有随相机移动的枪灯 |
| `zombies.js` | 对象池（手机 30 个，其他画质 43 个）；Mixamo 骨骼动画（待机、走、跑、爬、攻击、嘶吼、倒地）；按视线、距离和枪声感知；网格寻路加直线捷径；攻击在动作的实际出手帧结算；头、躯干、四肢分别用球和胶囊做命中检测。`spawn` 的选项可以指定是否奔跑、血量和伤害倍率、体型和 `rank`（`elite` / `boss` / `bloater`，带自发光）。每只僵尸有 `ctl { pin, rate, fear, push, lift }`，武器的定身、减速、恐惧、击退、挑飞写这里，`updateZombie` 照办 |
| `zombietune.js` | 僵尸的数值表（血量、速度、每下伤害、出手节奏、受击硬直、弱点大小、对象池），纯数据。`zombies.js` 以 `TUNE` 的名字用它，试验场测试台里的僵尸读的也是它 |
| `run.js` | 套餐关卡的导演：时间线刷怪、镬气与小票、调料效果、弹药掉落与补给箱、武器箱、红包与岔路、精英（一只比一只血厚）、关底、警报「爆单」、分店差异、解锁进度。通过 `pT` 传入的一组函数刷怪、刷新目标和标记 |
| `runtune.js` | 套餐的全部数值 `RUN`，纯数据；另有三个纯函数：`spiceValue`（调料几层是多少）、`weaponMods`（调料对武器的伤害、射速、换弹倍率）、`infusionsOf`（附魔调料每几次命中触发）。`run.js` 和试验场都读它 |
| `loadout.js` | 一局里的武器和弹药。武器不限数量；`AMMO` 是四种弹药池（上限、一包多少、开局多少），`ARMS` 是每把武器吃哪种、一发吃多少（这两张表试验场也读）。数字键 1–9 是捡到的顺序（`slot(n)`，1 是手枪），滚轮和手柄十字键左右是 `step(±1)`。步枪和手枪是游戏自己的枪（`own`），其余十二把交给 `armory.js`。它实现游戏武器系统的 `weapon.ext` 接口：手上是军械库武器时由它驱动每帧、提供 HUD 数字。子弹池就是步枪槽的备弹 |
| `armory.js` | 把 `arsenal/` 接进游戏。动态导入试验场的模块，给它一个「舞台」适配层（相机、场景、射线、借用游戏灯池里的灯），武器和双手挂在相机下、画在武器图层，按两边视场角的比例缩放；武器上的挂点换算成世界相机下的同屏位置，特效才从枪口出发。换弹从弹药池扣是通过 `lab.supply` 接到 `loadout.js` 的。试验场是按亮巷子调的，夜街曝光暗得多，所以所有特效着色器乘 `fxGain`，码头再乘 `stageGain` |
| `armtargets.js` | 试验场的战斗逻辑要的「靶子」接口，背后是游戏的僵尸：射线查询、把伤害转成 `z.damage` 并发出游戏原有的命中事件、把定身、恐惧和击退交给僵尸的 `ctl`。每只僵尸配一个 `mark` 对象。它不含任何规则：伤害结算、四种状态和反应都在 `arsenal/src/combat/status.js` |
| `range.js` | 靶场（`/?range=1`）。不是另一个模式，是 `run.js` 的同一局：`reset()` 时不排开局小票、不放开场的行尸，`update()` 里时间线（`spawnTick` / `eliteTick` / `bossTick`）换成 `range.update()`，战绩不入账。面板是一块 DOM（系统字体，只有中文，不进语言包），状态写进地址。僵尸：站桩是 `passive` 的僵尸摆在玩家面前、死了补；逼近是远处刷行尸走过来；尸潮直接用 `spawnTick`，把时间钉在所选那道菜的中点。精英、关底、胀尸和时间线用同一套配方（`eliteOpts` / `bossOpts` / `bloaterOpts`）。「数值」直接改内存里的共用数值表，再调 `retune()` 重算；`game.js` 里只有两处接线：`range` 参数等于自动开局，松开鼠标不算暂停（`RUN.mouseFree`） |
| `runhud.js` | 关卡界面的 DOM：倒计时与菜名、镬气条、调料、关底血条、提示、小票（三张，岔路时两张）、武器栏、弹药池。紧跟在原版 HUD 节点之后，随它显示和隐藏。武器栏按捡到的顺序排，桌面上标出数字键；触屏下没有弹药池那一排，每把武器前写它那种弹药的余量 |
| `wheel.js` | 武器轮盘的 DOM 和选择：带着的武器排成一圈，`push(dx, dy)` 把鼠标或右摇杆的转视角输入当成指针，按方向选中一把。按键和计时在 `run.js`：切枪键（Q、手柄 Y、触屏切枪）轻按回到上一把（触屏是下一把），按住 0.22 秒（触屏 0.32 秒）打开轮盘，街上降到 0.15 倍；松开、单击或数字键换上，触屏点一把或点空白处取消。轮盘开着时可以走，不能开火、不转视角；确认用的那次单击不会接着开枪 |
| `pickups.js` | 弹药包（四色）、红包、武器箱、补给箱指示灯。每种是几个 `InstancedMesh`，启动时一次建好（赶在着色器预编译之前），不新增光源。颜色是按夜街曝光写的不受光颜色，码头用 `setGain` 整体提亮 |
| `supplies.js` | 两关各十二个补给箱的位置。金龙街的箱子低于 0.47 m，不挡导航；码头的是 0.55 m 的木箱，带碰撞 |
| `docks.js` | 第二关（原版港口地图）在套餐里需要的补充，见上文「两关」 |
| `audio.js` | 采样的僵尸语音与脚步、城市环境声、三座警报器的空间循环声 |
| `eggs.js` | 彩蛋文案：心动冰室、TapTap 遊戲機中心、Cindy 士多三家店，街边两块黑板和冰室橱窗的菜单，卷闸上的海报。只放内容；店铺在 `level.js` 指定，黑板在 `dressing.js` 摆放，绘制由 `signs.menu` / `signs.eggPoster` 完成，并使用独立随机种子，改文案不会打乱街景的随机布局 |

新增招牌文字后要重新生成字体子集，新增道具后要更新素材清单，见 [素材来源与许可](assets.md)。

## 初始化顺序

1. 渲染器、场景、世界相机与武器相机。
2. 材质、物理、道具工厂、输入。
3. 关卡 → 远景 → 地面，然后 `physics.build()` 建立导航数据。
4. 特效、音频、玩家、战斗和爆炸物。
5. 武器、僵尸、HUD、任务状态机。
6. `render.onLevelReady()`：采集室内探针并预编译着色器，然后启动动画循环。

启动助手 `r` 捕获模块加载异常；渲染与关卡属于必要模块，其余在有替身实现时可以降级。因此 `__ready` 为真不代表所有系统正常，
仍应检查 `__errors`。局部点光源必须在第 6 步之前全部创建，之后增减灯数会触发全部材质重新编译。

军械库（`arsenal/` 的模块和十二把武器的模型）在第 5 步之后异步载入，赶不上第 6 步的预编译，所以 `armory.warmAll()` 自己做一遍：
把每把武器、双手和游戏自己的两把枪缩到千分之一、放在武器相机前画几帧。有两点容易错：
- 「几帧」必须是武器图层真的画了的帧（载入期间和等待时钟都不算），所以用一个什么都不写的三角形在 `onBeforeRender` 里计数。
- 手上的东西在室外和在街市大厅里用的是两张环境贴图（见渲染器里的 `interiorEnv`），各要一套着色器；预热时通过
  `render.envWarm = "out" | "in"` 让武器图层先后用这两张各画几帧。漏掉任何一套，第一次带着那把武器走进大厅就会卡一下。

## 每帧如何推进

由 `renderer.setAnimationLoop` 驱动，dt 最大截到 0.05 秒。顺序是：输入 → 游戏状态机 →（允许推进时）玩家、武器、僵尸、爆炸物 →
（非暂停时）特效、地面、关卡、远景、材质 → 音频、HUD → 渲染 → 清理输入的帧内状态。

`time.scale` 是街上的时间倍率：僵尸、爆炸物和关卡时钟乘以它，玩家和武器不乘。套餐里选小票时它降到 0.05（慢动作），
岔路小票 0.04，开局选第一把武器时 0.02，其余时候是 1。小票开着时 `run.js` 每帧清掉移动、转视角、开火、瞄准输入，
并放开鼠标锁定（`input.exitLock`）让玩家点小票，选完再 `input.requestLock`；`game.js` 在 `RUN.picking` 时不把失去锁定当成暂停。

事件总线用于 `enemy:killed`、`enemy:voice`、`game:state`、`objective:done`、`weapon:fire` 等联动，避免把所有逻辑塞进主循环。

## 性能约定

手机靠 `low` 档流畅运行，下面这些约定一旦被打破，帧率会明显回落。

- **画质档位**：`UM()` 把手机和平板（包括自称 Mac 的 iPad）判为 `low`。`low` 档的具体设置：
  - 画布最终输出最多 1.5 倍像素；
  - 闪光点光源 4 盏（其他档 6 盏），街区点光源 3 盏；
  - 软阴影 6+8 次采样；
  - 不做软粒子，也就不需要每帧拷贝深度（`?fxsoft=1` 可强制打开）；
  - 地面着色器带 `G_LITE`，雨水着色片段带 `SL_LITE`；反射关闭时地面带 `G_NOREFL`，跳过整段反射采样；
  - 招牌图集、僵尸贴图减半，各向异性过滤 2；
  - 灯笼摆动 20 Hz，僵尸只在 22 m 内投影；
  - 僵尸语音用 equal-power 声像；
  - 界面不用 `backdrop-filter`（`<html data-quality>` 控制）。

  `render.setQuality()` 切档时，会让带这些宏的材质重新编译。
- **两遍渲染的灯光布局必须一致**：世界一遍和武器一遍各看到 1 盏平行光、1 盏聚光灯和同样数量的点光源。
  因此武器补光是一盏远处的无衰减聚光灯，不是第二盏平行光。两遍不一致时，three.js 每帧会两次判定灯光状态变了，
  对所有材质重新推导着色器参数。
- **不要用 transmission（透射）材质**：只要视野里有一个透射网格，three.js 就会把所有不透明物体再画一遍到额外的多重采样目标。
  `kit.js` 会把 GLB 里的 `MeshPhysicalMaterial` 转成标准材质，玻璃改成普通半透明。
- **静态阴影缓存**：标了 `userData.staticShadow` 的网格（`kit.flush` 合并出的批次、合并后的原版道具）只画进一张缓存阴影图，
  每次更新阴影时把它拷进阴影图，再只画会动的投影物（僵尸、油桶、灯笼）。之后若新增、移动或隐藏这类网格，
  要调用 `G.render.invalidateStaticShadows()`。会动的东西不要打这个标记。
- **僵尸骨骼不在场景树里**：每个僵尸的骨骼挂在一个独立的 `holder` 上，动画推进或僵尸移动时由 `sync()` 手动更新世界矩阵。
  渲染器因此不用每帧遍历约 2000 个骨骼节点。池里闲置的僵尸也不在场景树里。命中检测在 `raycast` 时读取当前画面上的骨骼位置。
- **暂停时不重画**：暂停几帧之后画面停在最后一帧，窗口尺寸或画质改变才会重画。

## 试验场和本体共用的规则

武器在本体和试验场里跑的是同一份代码、读的是同一张表。改一处，两边一起变；不要在任何一边再写一份。

| 内容 | 唯一的出处 | 谁在用 |
| --- | --- | --- |
| 武器的模型、握法、换弹动作、特效、声音 | `arsenal/src/weapons/`、`kit/`、`fx/`、`audio/` | 两边 |
| 每种形态开火做什么，伤害、弹匣、射速、换弹时间 | `arsenal/src/combat/behaviours.js` | 两边 |
| 输入、后坐、换弹、近战、投掷、范围伤害；调料倍率怎么作用（`setMods`）；换弹从哪里拿子弹（`lab.supply`） | `arsenal/src/combat/combat.js` | 两边用同一个控制器 |
| 伤害结算、四种状态、四种反应、精英和关底的抗性、附魔调料怎么触发 | `arsenal/src/combat/status.js`，数字在 `arsenal/src/data/status.js` | 本体的 `armtargets.js` 和测试台的 `targets.js` 都只是它的宿主 |
| 每级的伤害倍率 | `arsenal/src/data/levels.js` | 两边 |
| 调料的层数和数值 | `src/chinatown/runtune.js` | `run.js`；测试台的 `combat/meal.js` |
| 四种弹药的上限、每把武器每发吃多少 | `src/chinatown/loadout.js` 的 `AMMO`、`ARMS`、`ammoPer` | `loadout.js`；测试台的 `combat/meal.js` |
| 僵尸的血量、速度、伤害、出手节奏、受击硬直、弱点大小 | `src/chinatown/zombietune.js` | `zombies.js`；测试台的 `targets.js` |
| 调料和弹药的名字 | `src/i18n/locales/zh-CN.js` | 两边 |

宿主（`status.js` 的 `createStatus(host)`）只需要提供：场上的僵尸列表、`hurt(z, dmg, o, direct)`（扣血、出血、死亡，返回是否击杀），
死亡时回调 `rules.died(z)`。僵尸对象上要有 `alive / type / rank / maxHp / radius / pos / chest / headPos / feet / vel / stagger`，
其余状态字段由 `clearStatus(z)` 建立。

**靶场就是游戏**：`/?range=1` 是同一个套餐，关掉时间线、加一块调试面板（`src/chinatown/range.js`），所以走位、拾取、精英、关底、胀尸、
LK-9 和 LK-4、命中体积、夜街的曝光和特效亮度都是真的，没有第二份。试验场的「靶场」按钮打开的就是它。

试验场里还留着一条巷子，叫「测试台」（`?mode=fp`）：给自动测试和测量脚本用，可以逐帧步进、几秒钟打完六十种形态。它的规则和数值与本体是同一份，
但僵尸只会直线走、命中体积是圆柱加头、光照是亮巷子——不要拿它调手感和特效亮度。

卡片和设计文档上的数值：基础形态的伤害、弹丸数、射程、溅射、弱点倍率、挥砍范围写在 `arsenal/src/data/weapons.js` 的 `fire` 里，`behaviours.js`
直接读它（`F.<武器>`）；射速、弹匣、换弹时间以 `behaviours.js` 的 `spec()` 为准，卡片读它，`arsenal/scripts/check-data.mjs` 再核对一遍数据里的那份
（`npm run check` 的一部分）。还是手写的只有岔路说明文字里的数字（「单发 150 伤害」这类），改岔路的数值时要一起改。

## 玩法与状态

状态为 `title`、`intro`、`playing`、`paused`、`dead`、`complete`。

- 套餐（内部模式名仍是 `mission`）：一关约十分钟的肉鸽关卡，规则在 `src/chinatown/run.js`。
  - `pT` 负责状态机、警报器交互和撤离判定；进入 `playing` 后每帧调用 `RUN.update(街上的 dt, 真实 dt)`。
  - 刷怪按 `RUN.stages` 的时间线：每道菜给出同时存活上限、刷新间隔、奔跑者和重型尸比例，在一道菜内线性过渡；
    难度（辣度）再乘一组系数。僵尸的生命和伤害仍由难度表决定。
  - 开局先开一次「点主菜」：三把已解锁的武器选一把（`time.scale` 0.02，最多等 20 秒）。
  - 击杀给镬气，升级后开三张小票（屏幕中央，街景压暗、上下黑边、准星和战斗按钮收起），`time.scale` 降到 0.05，
    玩家不能移动和开火，鼠标放开，点小票或按 1 2 3（手柄十字键、触屏点击）选择，没有时间限制。
    第 2、5、9、13 次升级的三张全是武器，其余每次有三成机会混入一把。
  - 武器和弹药归 `loadout.js`：四种弹药池只能靠掉落、补给箱、制服尸和警报箱补；`RUN.ammo` 是掉率和补给箱的数值。
    街上每局放五个武器箱（位置取自刷怪点），给一把还没有的武器，都有了就当一个红包。
  - 红包升的是捡到时手上那把（都满了就给一层随机调料并回满血）；升到三级时排一张两选一的「岔路」小票（甲 / 乙）。
    伤害倍率是 `arsenal/src/data/levels.js` 的 `LEVELS`，形态和终极词条来自 `arsenal/src/data/weapons.js`。
  - 四种附魔调料每隔几次命中给目标加一层状态：规则和状态、反应的结算都在 `arsenal/src/combat/status.js`
    （军械库武器的命中由它自己计数，步枪和手枪的命中由 `run.js` 转交给它）。
  - 解锁：`RUN.unlocks.start` 是开局可用的六把，`rules` 是其余每把的条件；`bank()` 在一局结束时把战绩记进
    `wokingdead.profile.v1` 并返回新解锁的武器，结算单上列出来。第一次在金龙街通关还会开放码头。
  - 精英每只比上一只多 `RUN.elite.hpGrow` 的血、`dmgGrow` 的伤害；胀尸爆炸对僵尸和对玩家是两个数（`RUN.bloater.damage` / `hurt`）；
    关底的血量、爪击和速度按辣度取 `RUN.difficulty` 里的 `bossHp` / `bossHit` / `bossSpeed`，登场时玩家回满血。
  - 警报器是可选项：切断后 `RUN.onSiren` 触发半分钟「爆单」。九分钟时关底出场，死后 `RUN.extractOpen` 为真，撤离点才生效。
  - 调料会改步枪和手枪的 `def.damage`、`def.rpm`、`weapon.reloadScale`，军械库武器的倍率交给战斗控制器
    （`combat.setMods`），另外改玩家的移动参数和生命上限；
    难度切换会重置玩家参数，`RUN.onTuning()` 负责重新套用。离开这个模式时 `RUN.stop()` 把这些都还原。
- 吃到饱（`holdout`）：持续波次，清场后休整、补给、治疗，再生成下一波，沿用原版规则。
- 原版任务流程（开局巡逻、切警报刷固定波次、全部切断后的追兵）的代码还在 `pT` 里，只有在 `run.js` 加载失败时才会用到。

难度表调整僵尸的生命、伤害、感知范围，以及吃到饱的奔跑比例和同时存在数量。设置保存在 `saltline.settings.v1`，无尽模式纪录另有存储键。

## 验证入口

- `npm run check`：全仓库语法检查和格式检查。
- `npm run test:e2e`：Playwright 真实点击冒烟测试（标题 → 开镬 → 暂停 → 死亡 → 重试，另查手机尺寸下按钮是否被遮挡），CI 上按需跑（PR 加 `e2e` 标签或手动触发）。
- `npm run build`：Vite 模块解析与生产打包。
- `/?autostart=1&noaudio=1`：启动冒烟检查；核对 `__ready`、`__fatal`、`__errors` 和 `__G.game.state`。
- `__G.game.debugCut()`：直接切断下一座警报器。
- `__G.run.debug`：`addXp(n)` 加镬气（触发升级）、`setTime(秒)` 跳到时间线上的某一刻（541 之后关底出场）、
  `envelope()` / `pack(种类)` 在身边放一个红包或弹药包、`give(id)` 给一把武器、`set(id, 等级, "a"|"b")` 直接把指定等级和
  形态的武器拿在手上；`__G.run.state` 是当前局的全部状态，`__G.run.loadout` 是武器和弹药，`__G.run.armory.debug.warmLog`
  是预热画过的武器。`/?unlock=all` 解锁全部武器和分店。
- `/?range=1`：靶场，见上文「试验场和本体共用的规则」和「唐人街模块」里的 `range.js`。调武器、调料、状态、僵尸数值都在这里做。
- `/?w=flamer&b=a&lv=5&spice=chili:2,fire:3`：和试验场同一组地址参数，带着这把武器的这个形态和这些调料开局（跳过开局的三选一）。
- `__G.physics.nav._grid()`：导航网格，改动布局后用它检查目标点和撤离点是否连通。
- 实际游玩还需验证瞄准、射击、换弹、暂停、目标推进与声音；构建成功不能替代这些检查。
- 界面改动后用真实点击走一遍：标题页切换语言 → 出发 → 选主菜 → 数字键换武器 → Esc 暂停 → 设置里换语言 → 继续 →
  死亡重试 → 通关再出发 → 换分店，并在桌面、手机竖屏、手机横屏（触屏）三种尺寸下各看一次。
- 查卡顿：每帧比较 `renderer.info.programs`，新出现的着色器程序连同它的 `cacheKey` 和已有程序逐项对比，
  差在哪一项（环境贴图尺寸、是否双面、灯数）就是没预热到的那一套。
