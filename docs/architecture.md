# 行尸走镬 Wok-ing Dead 架构与代码导航

## 先看什么

这是一个纯浏览器的第一人称射击游戏，用 Vite 提供开发服务和构建，游戏没有玩法后端，也没有 UI 框架；游玩统计另有 Vercel 日志接口（见 [telemetry.md](telemetry.md)）；界面由 DOM、模板字符串和 CSS 构成。

代码分两部分：

- `src/game.js`：原版发布包。Three.js r180 和整套游戏（渲染、材质、物理、武器、输入、HUD、任务）都在同一个闭包里，
  变量名是压缩后的。搜索函数声明或 `// ===` 分区标记来定位，不要依赖行号。
- `src/chinatown/`：唐人街版本新增的普通 ES 模块，负责关卡、远景、僵尸、音频和套餐（肉鸽关卡），通过游戏上下文对象与原版系统对接。
- `arsenal/`：十二把肉鸽武器的试验场，可单独运行。游戏通过 `src/chinatown/armory.js` 直接导入其中的武器模型、特效和战斗模块；
  反过来，试验场读本体的四张数值表（`runtune.js`、`loadout.js`、`zombietune.js`、两把本体枪的 `stockguns.js`）。武器在两边跑的是同一份规则，见下文「试验场和本体共用的规则」。
- `src/i18n/`：界面语言与界面字体。`game.js` 以 `L10N` 的名字导入它，HUD、菜单、无线电、加载提示里的所有文字都经由它取得。

推荐阅读顺序：`src/main.js` → `cL`（装配）→ `src/chinatown/level.js`（场景怎么搭）→ `pT`（状态机）→
`src/chinatown/run.js`（套餐关卡的规则）→ `src/chinatown/loadout.js` / `armory.js`（武器怎么接进来）→
`src/chinatown/zombies.js` → `xE` / `I5`（玩家、武器）→ `ov`（渲染）。

## 两部分怎么接在一起

- **同一个引擎实例**：`cL` 把内嵌的 THREE 命名空间发布到 `globalThis.__SALTLINE_THREE__`，`src/engine/three.js` 再把它按名字导出；
  `vite.config.js` 把 `three` 指向这个文件。因此 `three/examples` 里的 GLTFLoader、SkeletonUtils 以及新模块里的
  `import * as THREE from "three"` 用的都是游戏自己的那份引擎（package.json 里的 `three` 只为这些附加组件提供源码）。
- **上下文对象**：`cL` 创建的 `t`（调试时为 `window.__G`）含 THREE、参数、事件总线、随机数、时间、画质和 `util.mergeStatic`，
  各系统创建后挂回上面。新模块只通过它访问 `scene`、`mats`、`physics`、`props`、`events`、`player`、`camera`、`fx`。
- **世界参数**：`game.js` 的 `CT` 对象设置唐人街的世界参数：取消海面、扩大导航范围、黄昏天光（数值在 `src/chinatown/look.js`）、
  地面积水点位、路面标线和沥青着色器。`CT.apply()` 在任何系统创建之前执行。
- **地图**：只载入金龙街。港区地图、远景、分店选择、通关解锁和专用文案均已移除；旧的 `?lvl=harbor` 地址也载入金龙街。
  原版的地图和远景代码 `Pg` / `Iv` 已从运行时删除，可读快照在 [港区参考代码](../references/saltline-harbor/README.md)；共用的渲染、地面与道具系统继续使用。
- **材质**：`mats.adopt(material, { wet, macro, interior })` 把任意 `MeshStandardMaterial` 接进原版的雨水着色片段
  （淋湿变暗、垂直面水痕、室内探针），外部 PBR 贴图和 GLB 道具因此与原版表面一致。
- **替换点**：`cL` 中 `level`、`backdrop`、`enemies` 三个模块改为动态导入 `src/chinatown/` 下的实现；音频系统在原位置加载
  `src/chinatown/audio.js`。

## 配乐

`src/chinatown/music.js` 的 `createMusic` 替代运行时原版 `rE` 配乐器，沿用状态回调与音乐总线。
音频系统初始化时尝试 `AudioContext.resume()`，标题画面即可播放主曲；不等待这个 Promise，以免首次访问的自动播放限制卡住启动。
仍保留首次点击 / 按键解锁和后台挂起，浏览器未授权有声自动播放时需要一次用户交互。
`musicflow.js` 只读游戏上下文：28 米内追击的僵尸（8 米内权重更高）、`dishHot` 起灶引尸和仍存活的关底。
不使用套餐里“只要还有活尸就是 0.6”的音乐强度作为实际判断，不改刷怪或战斗规则；无上下文的隔离调用才用旧强度回退。
导演有升温 / 降温双门槛与保持时间，阻止来回切曲；计时使用 AudioContext 时间，不受小票慢动作影响，暂停时冻结。
日常曲为《雨夜开镬》第一版，尸潮曲为《尸潮开镬》第一版；`normal` / `horde` 对应这两种状态。
两首 MP3 在 `public/assets/audio/music/`，**不整首解码**：`fetch` 拿到压缩文件做成 blob 地址，交给 `<audio>` 元素边播边解，
经 `createMediaElementSource` 接进音乐总线。整首解码成 AudioBuffer 时两首约 110 MB，足以让 iPhone 杀掉页面（见 pitfalls.md）；
现在常驻内存的只有 6.5 MB 的压缩文件。每首两个播放器：快到结尾时第二个从起播位置开始，用 2 秒线性交叉衔接，
循环不会回到被跳过的前奏；源文件不改。iOS 要求每个媒体元素先在点击里播过一次，之后才能由帧循环启动，
所以前几次点击 / 按键会把四个元素静音地播一下再停（增益为零）；`navigator.audioSession` 设为 `ambient`，保持响铃开关静音时不出声。
`MUSIC_ENTRY` 设定日常 15 秒、尸潮 18 秒起播，跳过轻铺垫。
升温 3 秒、降温 6 秒等功率交叉淡化；两首只在过渡期间同时播放，淡出完成后暂停旧曲，保存游标供下一次使用。
AudioContext 挂起（切后台）时音乐元素一起暂停，回来后从原位置继续。
暂停保存两首位置和过渡进度，继续时恢复；新曲加载完成前保留可用曲，失败记录到 `__G.audio.music.debug()`，不阻断游戏。
枪声压低音乐、主音量、后台音频挂起沿用原总线。原版合成配乐只保留给离线 `selfTest`；正常游戏不预生成 `music_*` / `mus_*`。
`fetch` 读取兼容单文件版资源映射；这两首并非分轨或严格节拍同步素材，衔接和混音仍需试听。

`audiovolume.js` 按原始混音值缩放音乐总线及其余音效总线，不反复乘当前增益；唐人街直接混响发送另经音效增益，避免绕过音效静音。
音乐和音效共用原有末级压缩 / 混响，但输入音量独立；调零后已发出的混响尾音自然衰减。设置中的 `musicVolume` / `effectsVolume`
默认 1，沿用 `saltline.settings.v1`，启动时与保存的主音量一起应用，避免静音存档开场漏声；滑杆调整以 20ms 时间常数平滑。

## 多语言与界面

- **语言包**：`src/i18n/locales/{en,zh-CN,zh-TW,ja}.js`，扁平的键值表。英文是基准，其他语言缺键时回退到英文；
  `{n}` 这样的占位符由 `t(key, vars)` 填入；键名以 `Html` 结尾的值是受信任的标记（只用 `<kbd>`）。
- **选择顺序**：`?lang=` → localStorage `wokingdead.lang`（兼容旧的 `ghostmarket.lang`） → 浏览器语言 → 英文。`setLocale()` 设置 `<html lang>` 和
  `data-script`（`latin`/`sc`/`tc`/`jp`），CSS 据此收紧中日文的字距和行高。
- **静态文字**：菜单和 HUD 的标记里用 `data-i18n`（文本）、`data-i18n-html`（标记）、`data-i18n-aria`（无障碍标签），
  切换语言时 `applyDom()` 统一刷新。
- **动态文字**：目标、提示、弹药提示、击杀播报、波次警告在显示时调用 `L10N.t()`；无线电台词 `Vu` 是一组 getter，入队时取当前语言。
  `sT`（HUD）、`hT`（菜单）、`pT`（任务）各自用 `L10N.onLocale()` 在切换后重画罗盘、目标、结算与死亡统计等已显示的内容。
- **字体**：全部通过 `FontFace` 加载（单文件版的 URL 映射依赖这一点）。拉丁界面字体（Inter、Noto Serif Display）总是加载；
  中日文字体只加载当前语言那一份，换语言时替换。中日文语言下拉丁字体用 `unicodeRange` 让出 `· — … “ ”`，这些标点改用全角字形。
  场景贴图用的 Big Shoulders / Barlow Condensed / IBM Plex Mono 也在这里注册。
- **界面结构**：标题页（品牌标志、语言切换、出发/设置/操作、模式与难度、操作速查）、暂停/死亡/结算卡片、右侧设置抽屉
  （设置、操作、关于）都由 `hT` 生成，样式在 `src/style.css` 开头的设计变量里统一定义（墨黑、宣纸白、朱砂、玉绿）。

## 关卡接口

`createLevel(G)` 返回的对象与原版 `Pg` 相同，其他系统依赖这些字段：

| 字段 | 用途 |
| --- | --- |
| `playerStart` | 出生位置和朝向 |
| `objectives[]` | `{ id, label, zone, pos, object }`，`object.userData.setState("live" \| "cutting" \| "cut")` 驱动警报器外观 |
| `extraction` | 撤离点位置与半径 |
| `enemySpawns[]` | `{ pos, zone, type: "ground" }`；创建时会剔除不可走或与出生点不连通的点 |
| `spawnRegions[]` | 可选的院落范围与入口线段；关帝庙的正门、侧门与造墙时共用坐标，刷新选点按真实路线经过的门统计压力 |
| `interiorBoxes[]` | 室内范围（街市大厅）：渲染器在此采集室内环境探针，雨、地面湿度、音频混响都据此切换 |
| `cinematicPath[]` | 标题画面和 `?bench=1` 的镜头路径 |
| `explosives[]` | 可引爆的油桶、气瓶，由爆炸物系统生成 |
| `supplySites[]` | 补给箱：`{ id, pos, yaw, top }`，金龙街十二处，箱子烘进静态街景；哪八个有货、各是哪种弹药由 `run.js` 每局随机决定 |
| `groundSurfaceAt(x, z)`、`update(dt)` | 脚步材质；每帧更新（灯光调度、灯笼摆动、警报器、血泊） |

物理是原版的轴对齐包围盒世界：`physics.addBox` 加碰撞，`playerOnly` 的盒子挡人和导航但不挡子弹。
`navigation.js` 提供 `physics.nav`：0.25 m 网格，格子中心走不通时补采障碍物边缘的通行位置，避免窄缝随网格对齐方式消失。
身体半径 0.3 m、高 1.7 m；玩家和僵尸共用 `STEP_HEIGHT`（0.42 m），导航按脚下高度检查连续台阶，路径连线和捷径也逐段检查身体、落脚与头顶空间。
靠墙只增加少量选路代价，不封掉实际能走的路。实心的 `noNav` 物体仍参与导航，`bulletOnly` 不参与。
当前是单层地面导航，落脚面最高 1.5 m（与僵尸出生的 `groundHeight` 查询一致），没有跳跃、攀爬或跨层路径。
静态碰撞按空间分桶，连通区域在载入时计算、边检查结果复用；增删碰撞盒只重采附近格子和边，再更新连通区域，避免炸一个油桶就重查整张地图的几何。`build()` 可强制全量重建。
寻路用带小幅目标偏好的 A*，捷径用倍增探测减少重复扫同一段街道；出生点过滤也用真实路径连通关系，不能仅按相邻空格判断。

`crowd.js` 让尸群在无遮挡的接近方向上错开目标，并提前向同伴旁边的空位避让；窄门没有余地时保持原路径。
偏移和分离都检查通路，最后仍经真实碰撞移动；完全重叠的出生位置有稳定的分离方向，定身和挑飞不会被分离推走。
追击和刷怪选点使用 `findPath` 的 `approach` 选项：高处目标不可达时，在目标周围 8 m 内寻找与出发点连通、最靠近目标的落点；普通寻路仍要求精确到达。
`zombies.js` 每帧最多重新寻路三次，找不到路就等待下一次计算；沿已经检查过的路径方向移动，模型朝向平滑跟上，避免转身弧线切进墙角。

`spawning.js` 负责地面僵尸的刷新位置，套餐和吃到饱共用。先剔除距离不足、不可走、玩家正前方看得见的点，优先选遮挡后的点；
再按最后的接近路线分组，庙院内按正门、侧门分组，其他位置按路线最后 8 m 的方向分成六组。用概率挑选方向和位置：
最近 12 秒刷过的附近区域、已经有较多活尸的方向会降权，同一扇门背后有更多刷新点不会因此获得更多票数。
每次最多新查四个候选的路线，加一次最终散开位置的路线检查；玩家移动超过 2 m、跨过阻挡或院落边界、导航 `revision` 变化时清理路线缓存。
快尸小队的偏移也检查距离、视线和通路；排队的僵尸真正出现前重新检查位置。没有合适位置时稍后重试，不回退到身边的随机点。
开局的游走行尸仍由 `run.js` 按整张可行走区域散布，刷新数量、类型与节奏仍由原有时间线决定。每局重开清空选点记录。

验证：`npm run test:navigation` 用实际碰撞函数检查不同网格偏移的窄门、连续台阶、墙角、低顶和尸群避让；
也检查双门分流、局部重复刷新、视线和距离。`tests/e2e/navigation.spec.js` 通过真实点击进入一局后，推进实际僵尸更新，检查主街横向展开与街市、庙院等位置的追击；
`tests/e2e/spawning.spec.js` 检查庙院三个站位的两门来敌、套餐实际刷新与快尸散开，以及排队时玩家走近后重新选点。

## 唐人街模块

| 模块 | 做法 |
| --- | --- |
| `kit.js` | 载入 PBR 贴图组和 GLB 道具；提供以米为单位自动展 UV 的盒子、四边形、圆柱、细杆、悬链线；所有静态几何按材质合并成少量网格；纯色表面共用带顶点色的材质 |
| `buildings.js` | 一栋楼是带真实窗洞的薄壳。临街立面按开间生成店面（卷闸、半拉卷闸、玻璃橱窗、住宅门、黑洞门口）、牌匾或灯箱、竖招牌、阳台、消防梯；橱窗和半拉卷闸后面的房间、店面上的遮阳篷交给 `shopfit.js`；后巷立面是后门、铁窗、水管、空调和污渍。远景用 `simple` 选项省掉窗框 |
| `signs.js` | 四张 Canvas 图集：霓虹/灯箱（自发光）、漆面牌匾与海报（受光）、亮窗（自发光）、血迹与窗棂（带透明）。图集用天际线装箱 |
| `shopfit.js` | 店铺内景与遮阳篷。每个玻璃店面或半拉卷闸后面是一间真实的房间（杂货铺、茶餐厅、药材铺、烧腊店、茶庄），货架、柜台、桌椅、货品都是几何体，用一张 2048 图集上的包装、菜单、字画贴图。房间不占用光源：载入时按房间里的灯位逐顶点烘焙光照（对家具做阴影射线、墙角压暗、街上透进来的冷光），用不受光的顶点色材质绘制。楼房生成时只登记房间，`finish()` 统一规划（街角两家店互相让位、进深不超过楼的一半）后建成，按街区合并；地板墙面单独成网格以便出现在湿路面倒影里。低画质和远景街区用简化版。遮阳篷是带下垂和扇贝边的帆布，中间缝着店名 |
| `market.js` | 街市大厅：砖墙铁皮棚，主过道上方两跨是玻璃天窗（不受光材质，放在倒影图层里，室内环境探针因此能采到天光）。十字过道之间按行当摆档口——冰鲜、活海鲜鱼缸、鲜肉、活禽、鸡蛋、干货、豆腐、蔬菜、水果、粮油、粉面，各有柜台、货品、档口牌、吊灯和帆布顶。货品、招牌、价钱牌、水缸、地面水渍都来自一张 Canvas 图集，经哑光、亮面、自发光、透明四个共用材质绘制，颜色靠顶点色区分，所以整个大厅只有几次绘制调用 |

## 初始化顺序

1. 渲染器、场景、世界相机与武器相机。
2. 材质、物理、道具工厂、输入。
3. 关卡 → 远景 → 地面，然后 `physics.build()` 建立导航数据。
4. 特效、音频、玩家、战斗和爆炸物。
5. 武器、僵尸、HUD、任务状态机。
6. `render.onLevelReady()`：采集室内探针并预编译着色器，然后启动动画循环。

启动助手 `r` 捕获模块加载异常；渲染与关卡属于必要模块，其余在有替身实现时可以降级。因此 `__ready` 为真不代表所有系统正常，
仍应检查 `__errors`。局部点光源必须在第 6 步之前全部创建，之后增减灯数会触发全部材质重新编译。

军械库（`arsenal/` 的模块和十二把武器的模型）在第 5 步之后异步载入，赶不上第 6 步的预编译，所以 `armory.warmAll()` 自己做一遍：
把每把武器、双手和游戏自己的两把枪缩到千分之一、放在武器相机前画几帧。有两点容易错：
- 「几帧」必须是武器图层真的画了的帧（载入期间和等待时钟都不算），所以用一个什么都不写的三角形在 `onBeforeRender` 里计数。
- 手上的东西在室外和在街市大厅里用的是两张环境贴图（见渲染器里的 `interiorEnv`），各要一套着色器；预热时通过
  `render.envWarm = "out" | "in"` 让武器图层先后用这两张各画几帧。漏掉任何一套，第一次带着那把武器走进大厅就会卡一下。

## 每帧如何推进

由 `renderer.setAnimationLoop` 驱动，dt 最大截到 0.05 秒。顺序是：输入 → 游戏状态机 →（允许推进时）玩家、武器、僵尸、爆炸物 →
（非暂停时）特效、地面、关卡、远景、材质 → 音频、HUD → 渲染 → 清理输入的帧内状态。

`time.scale` 是街上的时间倍率：僵尸、爆炸物和关卡时钟乘以它，玩家和武器不乘。套餐里选小票时它降到 0.05（慢动作），
岔路小票 0.04，开局选第一把武器时 0.02，其余时候是 1。小票开着时 `run.js` 每帧清掉移动、转视角、开火、副攻击输入，
并放开鼠标锁定（`input.exitLock`）让玩家点小票，选完再 `input.requestLock`；`game.js` 在 `RUN.picking` 时不把失去锁定当成暂停。

事件总线用于 `enemy:killed`、`enemy:voice`、`game:state`、`objective:done`、`weapon:fire` 等联动，避免把所有逻辑塞进主循环。

## 性能约定

手机靠 `low` 档流畅运行，下面这些约定一旦被打破，帧率会明显回落。

- **画质档位**：`UM()` 把手机和平板（包括自称 Mac 的 iPad）判为 `low`。`low` 档的具体设置：
  - 画布最终输出最多 1.5 倍像素；
  - 闪光点光源 4 盏（其他档 6 盏），街区点光源 3 盏；
  - 软阴影 6+8 次采样；
  - 不做软粒子，也就不需要每帧拷贝深度（`?fxsoft=1` 可强制打开）；
  - 地面着色器带 `G_LITE`，雨水着色片段带 `SL_LITE`；反射关闭时地面带 `G_NOREFL`，跳过整段反射采样；
  - 招牌图集、僵尸贴图减半，各向异性过滤 2；
  - 灯笼摆动 20 Hz，僵尸只在 22 m 内投影；
  - 僵尸语音用 equal-power 声像；
  - 界面不用 `backdrop-filter`（`<html data-quality>` 控制）。

  `render.setQuality()` 切档时，会让带这些宏的材质重新编译。
- **手机的内存上限**（iPhone 把网页进程和它的显存算在一起，iPhone Air 约 2 GB，超了整页被杀）：手持设备上 `texmem.js` 在贴图上传后
  释放原图（`game.js` 里 three.js 上传 2D 贴图处调 `afterUpload`）。解码图片总是释放；画布只在标了 `markStatic` 后释放
  （建筑贴图、招牌图集最后一次 `finish`、僵尸贴图缩小、武器库 `kit.canvas`）。武器库画布在 `low` 档是半分辨率（`createKit({ canvasScale })`）。
  音乐用 `<audio>` 边播边解，不整首解码。
- **两遍渲染的灯光布局必须一致**：世界一遍和武器一遍各看到 1 盏平行光、1 盏聚光灯和同样数量的点光源。
  因此武器补光是一盏远处的无衰减聚光灯，不是第二盏平行光。两遍不一致时，three.js 每帧会两次判定灯光状态变了，
  对所有材质重新推导着色器参数。
- **不要用 transmission（透射）材质**：只要视野里有一个透射网格，three.js 就会把所有不透明物体再画一遍到额外的多重采样目标。
  `kit.js` 会把 GLB 里的 `MeshPhysicalMaterial` 转成标准材质，玻璃改成普通半透明。
- **静态阴影缓存**：标了 `userData.staticShadow` 的网格（`kit.flush` 合并出的批次、合并后的原版道具）只画进一张缓存阴影图，
  每次更新阴影时把它拷进阴影图，再只画会动的投影物（僵尸、油桶、灯笼）。之后若新增、移动或隐藏这类网格，
  要调用 `G.render.invalidateStaticShadows()`。会动的东西不要打这个标记。
- **僵尸骨骼不在场景树里**：每个僵尸的骨骼挂在一个独立的 `holder` 上，动画推进或僵尸移动时由 `sync()` 手动更新世界矩阵。
  渲染器因此不用每帧遍历约 2000 个骨骼节点。池里闲置的僵尸也不在场景树里。命中检测在 `raycast` 时读取当前画面上的骨骼位置。
- **闪电借用主光**：闪电的前半秒，渲染器把唯一投影的那盏平行光借给闪电（变冷、变亮、改从闪电那一侧的高处照下来），之后还回去，灯的数量和布局不变。
  光一动，静态阴影缓存会自己重画，一去一回各一次；`low` 档不做（只保留天空闪光），省掉手机上的这两次重画。街道探针（`render.streetEnv`）和街市大厅的探针同尺寸，
  手上的东西因此仍然只有两套着色器。
- **`game.js` 静态导入的模块不能导入 `three`**：那时引擎还没发布到 `globalThis`。`look.js`、`streetfx.js` 因此是纯数据和字符串，要建贴图就由拿得到 THREE 的一方来建。
- **暂停时不重画**：暂停几帧之后画面停在最后一帧，窗口尺寸或画质改变才会重画。

宿主（`status.js` 的 `createStatus(host)`）只需要提供：场上的僵尸列表、`hurt(z, dmg, o, direct, fate)`（扣血、出血、死亡，返回是否击杀；`fate` 是这一下如果打死了尸体会怎样：打飞多远、掉哪几截），
死亡时回调 `rules.died(z)`。僵尸对象上要有 `alive / type / rank / maxHp / radius / pos / chest / headPos / feet / vel / stagger`，
其余状态字段由 `clearStatus(z)` 建立。

**靶场就是游戏**：`/?range=1` 是同一个套餐，关掉时间线、加一块调试面板（`src/chinatown/range.js`），所以走位、拾取、精英、关底、胀尸、
LK-9 和 LK-4、命中体积、夜街的曝光和特效亮度都是真的，没有第二份。试验场的「靶场」按钮打开的就是它。

试验场里还留着一条巷子，叫「测试台」（`?mode=fp`）：给自动测试和测量脚本用，可以逐帧步进，几分钟打完 66 种形态（包括本体两把枪的替身）。它的规则和数值与本体是同一份，
但僵尸只会直线走、命中体积是圆柱加头、光照是亮巷子——不要拿它调手感和特效亮度。

卡片和设计文档上的数值：基础形态的伤害、弹丸数、射程、溅射、弱点倍率、挥砍范围写在 `arsenal/src/data/weapons.js` 的 `fire` 里，`behaviours.js`
直接读它（`F.<武器>`）；射速、弹匣、换弹时间以 `behaviours.js` 的 `spec()` 为准，卡片读它，`arsenal/scripts/check-data.mjs` 再核对一遍数据里的那份
（`npm run check` 的一部分）。还是手写的只有岔路说明文字里的数字（「单发 150 伤害」这类），改岔路的数值时要一起改。

当前所有武器都不开镜瞄准；鼠标右键、手柄 LT 和触屏「副攻击」只用于武器的副攻击（按住使用、松开结束）。原版输入字段 `ads` 暂留作副攻击通道，不代表开镜。未来只有为狙击枪等设计了有意义的机制后才重新引入瞄准。

手机的副攻击键用闪电线条图标，只在当前武器的当前分支有副攻击时显示。`armory.hasSecondary` 同时读取共用战斗行为的 `alt` 和该分支的 `hint`，不另列一份武器名单；礼花的主攻击蓄力提示不会误显示副攻击键。切到没有副攻击的武器时收起按钮并清掉该触屏按压。

## 玩法与状态

状态为 `title`、`intro`、`playing`、`paused`、`dead`、`complete`。

- 套餐（内部模式名仍是 `mission`）：一关约十分钟的肉鸽关卡，规则在 `src/chinatown/run.js`。
  - `pT` 负责状态机、警报器交互和撤离判定；进入 `playing` 后每帧调用 `RUN.update(街上的 dt, 真实 dt)`。
  - 刷怪按 `RUN.stages`，读的是套餐的钟（见下文三口灶）：每道菜给出同时存活上限、刷新间隔、奔跑者和重型尸比例，在一道菜内线性过渡；
    难度（辣度）再乘一组系数。僵尸的生命和伤害仍由难度表决定。
  - 开局先开一次「点主菜」：三把已解锁的武器选一把（`time.scale` 0.02，最多等 20 秒）。
  - 开局街上散布 `RUN.opening` 只游走的行尸（`spawn` 的 `dull: true`）；标了 `quiet` 的菜（前菜）刷出来的也是。
    游走的行尸在没盯上人之前用 `ZOMBIES.wander` 的感知（视野 9 米、贴近 5 米、枪声 14 米、同伴的嚎叫 7 米），
    会沿街漂移；被打、被走近或听到近处的枪声后就和普通行尸一样。
  - 套餐里不自动回血（`RUN.heal.regen` 是保留的比例，现在是 0）。击杀按 `runflow.js` 的 `foodChance` 掉外卖盒，
    它和弹药包走同一套拾取（`pickups.js` 里种类是 `food`），满血时留在地上。
  - 换弹装满全部：手上的武器换弹完成时，`loadout.js` 的 `reloadRest` 把收着的每把也从各自的弹药池装满
    （军械库武器走 `hooks.loaded`，游戏自带的两把听 `weapon:reload` 的 `magin`）。
  - 补给箱与普通弹药掉落一样，靠自身灯光辨认，没有发现判定、指南针或屏幕距离标记；领取时共用普通弹药的图标与「+数量」提示。
  - 谁演谁在 `RUN.bodies`：关底、两种精英、胀尸、快尸各指定一个 `zombietune.js` 的 `EXTRA_BODIES` 模型和体型。
    一局开始时 `fetchBodies` 去下载（`low` 画质一个一个地下，免得五份原图同时在内存里）；角色贴图留多大按画质查
    `zombietune.js` 的 `BODY_TEX`，手机和电脑同一张表。开机的画质是地址里的 `?q=`、其次是保存的设置（`src/bootguard.js` 的
    `presetToBoot`）、最后才是按设备自动选，所以僵尸的对象池和贴图跟着玩家选的档位走；手机上高于 `low` 的档位算试用：
    页面在前台时留一个 `wokingdead.boot` 标记，正常切走或关闭时擦掉，下次开机发现标记还在就说明上次被浏览器杀掉了，
    设置退回自动档；`withBody` 在模型到位后才把 `body` 写进刷怪选项，并把原来的
    彩色发光压到 `RUN.bodies.glow`。模型没到、该模型的骨架都在场上、或靶场指定了别的模型（`zombies.cast`）时，
    照旧用原来的角色加发光（`spawnAt` 的 `plain`）。精英按 `RUN.elite.kinds` 轮流（`runflow.js` 的 `eliteKind`）；
    快尸是 `spawnKind` 返回的 `pack`，一次在同一个刷怪点放 `RUN.pack.size` 只。
  - 三口灶沿用原版「切断警报器」的目标机制（`level.objectives`、`objective:done`；原版是按住 E，套餐里按一下就点着）：模型是 `stove.js` 的
    `buildStove`（在 `landmarks.js` 里摆），状态经 `userData.setState`
    设置。按住完成时 `game.js` 调 `RUN.onStove`：`run.js` 用 `runflow.js` 的 `newDish` 记下 `S.cook`，把游走的行尸全部引来。
    一道菜是三次颠锅、每次颠完菜在灶上自己炒一段、最后打包，规则都在 `runflow.js` 的 `dishStep`（时长、每段开场来什么在 `RUN.stove`）：
    - 颠锅：锅拿在手上（`S.hands = "wok"`，手上的武器收起，不能开枪也不能冲刺，可以走），`toss.seconds` 秒里颠 `toss.flips` 次，
      每次 `flare()` 朝身前喷火（伤害、灼烧层数、击退在 `toss.flare`）。颠完要走回灶边 `toss.reach` 米内，锅自动放回，才开始炒。
      第一次颠锅在起灶的同时开始；后两次要回灶边按一下 E。套餐里起灶、拿锅、打包都是按一下，没有按住的进度圈
      （提示条的 `setPrompt(文字, 0, true)`），进度就是手上的颠锅和打包动作本身。
    - 炒（`fry`）：菜自己在灶上炒，人在哪都计时，没有「守」这回事；第二段开场来几群快尸（`packs`），第三段来一只精英（`elite`）。
    - 对玩家唯一的约束是到点回灶：该颠第二、三次或该打包了没人接手，过了 `burn` 秒菜糊一次，每糊一次奖励降一档（`dishGrade`）；
      糊了再放 `char` 秒就烧焦，只能打包，照样算一袋外卖但什么都不给（`dishOf` 的 `charred`，打包动画里装的是同一份饭，只是全黑了）。
      糊了的灶冒黑烟（`wokhand.js` 的 `smoke`）。
    - 第三段炒完回灶边按一下 E 打包（`S.hands = "pack"`，`pack` 秒），包完 `serve` 发奖。三种招牌每局洗一次（`S.menu`）。
    - 该做什么只说一次：共用漫画对话（`runhud.js` 的 `setCook` → `comms.js`），用后厨喊话的口气说现在该做什么、还剩几秒，
      不报「第几次」，三次颠锅各有各的说法（`run.cook.toss0` … `fry2`）。别处不重复：炒菜对话替换当前无线电及其队列，步骤结束前不插播其他台词，
      灶上的标记只写「锅」和距离，用来指回去的方向；左上角不重复显示炒菜目标，右下角在双手占着时不显示弹药（`setHands`）。
      炒菜对话是 HUD 里用后厨喊话口气的地方。
    - 灶上有菜时不能点别的灶（`RUN.cooking`），灶边的提示条来自 `RUN.stovePrompt()`，目标文字来自 `RUN.objective()`。
    刷怪加码（`spawnPace` 的 `cooking` / `heat`）只在菜还「烫」着的时候（`dishHot`：从起灶到第三段炒完）。
    加码是逐级来的：`RUN.stove.swell` 是三次颠锅各自那一段的尸潮占满额的比例（`spawnPace` 的 `step`），
    `smell` 是每次颠锅时街上已有的僵尸在多远之内会被引来，所以第一次端锅时人少，第三次颠完最多。
    定时的精英（`runflow.js` 的 `timedElite`）灶上有菜时不来，第三道菜打包后不再来，两口灶之间最多来 `RUN.elite.idle` 只，
    所以拖着不起灶刷不到更多红包。
    灶上那锅菜就是手上颠的那一锅：`wokhand.js` 的 `dish` 是同一堆饭团按灶上的锅重新摆好，`run.js` 用灶的 `setDish` 放进去（`plate`），
    炒的时候 `sizzle` 让它微微抖，该颠了抖得更厉害，烧焦了整堆变黑（`charDish`，还是同一堆饭，换成发黑的材质）。军械库没载入时灶用自己画的一团饭。
    锅在灶上时火从锅底和桶沿之间的缝里出来，沿锅的外壁往上、越过锅沿（`stove.js` 的 `CURTAIN`），锅里面没有火。
    锅端走时（灶的 `toss` 状态）灶口露出炉头：`stove.js` 画炉头、从上面看得到的火床和收成一束的火舌，
    离开炉口的火苗和火星是 `wokhand.js` 的 `burner()` 发的粒子（军械库没载入时只有前者）。
    灶的声音在 `audio.js`（听 `stove:state`）；原来的警报声保留代码但关掉了（`SIREN.on`）。
  - 套餐的钟（`S.clock`，`runflow.js` 的 `clockStep`）：`RUN.stages` 是按它读的，不是按街上的时间。灶上有菜时它和街上一样快，
    没有菜时只走 `RUN.simmer` 倍，并且停在每道菜的末尾等下一口灶：点第一、二、三口灶分别进入第二、三、四道菜。
    第三道菜打包后 `RUN.boss.after` 秒关底出场，所以三口灶是必经的，一局多长由玩家什么时候起灶决定。
  - 击杀给镬气，升级后开三张小票（屏幕中央，街景压暗、上下黑边、准星和战斗按钮收起），`time.scale` 降到 0.05，
    玩家不能移动和开火，鼠标放开，点小票或按 1 2 3（手柄十字键、触屏点击）选择，没有时间限制。
    第 2、5、9、13 次升级的三张全是武器，其余每次有三成机会混入一把。
  - 武器和弹药归 `loadout.js`：四种弹药池只能靠掉落、补给箱、制服尸和警报箱补；`RUN.ammo` 是掉率和补给箱的数值。
    街上每局放五个武器箱（位置取自刷怪点），给一把还没有的武器，都有了就当一个红包。
  - 红包升的是捡到时手上那把（都满了就给一层随机调料并回满血）；升到三级时排一张两选一的「岔路」小票（甲 / 乙）。
    伤害倍率是 `arsenal/src/data/levels.js` 的 `LEVELS`，形态和终极词条来自 `arsenal/src/data/weapons.js`。
  - 四种附魔调料每隔几次命中给目标加一层状态：规则和状态、反应的结算都在 `arsenal/src/combat/status.js`
    （军械库武器的命中由它自己计数，步枪和手枪的命中由 `run.js` 转交给它）。
  - 解锁：`RUN.unlocks.start` 是开局可用的六把，`rules` 是其余每把的条件；`bank()` 在一局结束时把战绩记进
    `wokingdead.profile.v1` 并返回新解锁的武器，结算单上列出来。
  - 精英每只比上一只多 `RUN.elite.hpGrow` 的血、`dmgGrow` 的伤害；胀尸爆炸对僵尸和对玩家是两个数（`RUN.bloater.damage` / `hurt`）；
    关底的血量、爪击和速度按辣度取 `RUN.difficulty` 里的 `bossHp` / `bossHit` / `bossSpeed`，登场时玩家回满血。
  - 关底死后 `RUN.extractOpen` 为真，撤离点才生效，走到就通关。
  - 调料会改步枪和手枪的 `def.damage`、`def.rpm`、`weapon.reloadScale`，军械库武器的倍率交给战斗控制器
    （`combat.setMods`），另外改玩家的移动参数和生命上限；
    难度切换会重置玩家参数，`RUN.onTuning()` 负责重新套用。离开这个模式时 `RUN.stop()` 把这些都还原。
- 吃到饱（`holdout`）：持续波次，清场后休整、补给、治疗，再生成下一波，沿用原版规则。
  专属开场、接敌、低血量和清波对白由 `holdout-dialogue.js` 读取语言包，清波六句按波次轮换；套餐仍用自己的对白。
- 原版任务流程（开局巡逻、切警报刷固定波次、全部切断后的追兵）的代码还在 `pT` 里，只有在 `run.js` 加载失败时才会用到。

难度表调整僵尸的生命、伤害、感知范围，以及吃到饱的奔跑比例和同时存在数量。设置保存在 `saltline.settings.v1`，无尽模式纪录另有存储键。

## 验证入口

- `npm run check`：全仓库语法检查和格式检查。
- `npm run test:e2e`：Playwright 真实点击冒烟测试（标题 → 开镬 → 暂停 → 死亡 → 重试，另查手机尺寸下按钮是否被遮挡），暂停使用，需要时再跑。
- `npm run build`：Vite 模块解析与生产打包。
- `/?autostart=1&noaudio=1`：启动冒烟检查；核对 `__ready`、`__fatal`、`__errors` 和 `__G.game.state`。
- `__G.game.debugCut()`：直接切断下一座警报器。
- `__G.run.debug`：`addXp(n)` 加镬气（触发升级）、`setTime(秒)` 把套餐的钟拨到某一刻（540 起算作三道菜都已打包，关底马上出场）、
  `skipDish()` 把灶上那道菜推到当前这一步的末尾（颠完、炒完、等到糊或烧焦、包完）、
  `envelope()` / `pack(种类)` 在身边放一个红包或弹药包、`give(id)` 给一把武器、`set(id, 等级, "a"|"b")` 直接把指定等级和
  形态的武器拿在手上；`__G.run.state` 是当前局的全部状态，`__G.run.loadout` 是武器和弹药，`__G.run.armory.debug.warmLog`
  是预热画过的武器。`/?unlock=all` 解锁全部武器。
- `/?range=1`：靶场，见上文「试验场和本体共用的规则」和「唐人街模块」里的 `range.js`。调武器、调料、状态、僵尸数值都在这里做。
- `/gallery/`：陈列馆，就是 `arsenal/` 的展柜（只有展柜，没有测试台）。`vite.config.js` 里的插件在每次构建站点时调
  `arsenal/scripts/showcase.mjs` 把它做成一个自带全部代码的页面放进 `dist/gallery/`，所以它跟游戏一起部署、不会差一个版本；
  开发服务器上 `/gallery/` 会转到试验场自己的服务器（`npm run arsenal`，5311 端口）并用 `?home=` 告诉它游戏在哪。
  首页、靶场、陈列馆三处互相跳转用的地址都在 `src/chinatown/doors.js`，都是整页跳转。
- `/?w=flamer&b=a&lv=5&spice=chili:2,fire:3`：和试验场同一组地址参数，带着这把武器的这个形态和这些调料开局（跳过开局的三选一）。
- `__G.physics.nav._grid()`：导航网格，改动布局后用它检查目标点和撤离点是否连通。
- `__G.game.spawnDirector.debug.last`：最近一次选点的位置、实际入口、候选入口与寻路次数；没有安全位置时记录原因。
- 实际游玩还需验证副攻击、射击、换弹、暂停、目标推进与声音；构建成功不能替代这些检查。
- 界面改动后用真实点击走一遍：标题页切换语言 → 出发 → 选主菜 → 数字键换武器 → Esc 暂停 → 设置里换语言 → 继续 →
  死亡重试 → 通关再出发，并在桌面、手机竖屏、手机横屏（触屏）三种尺寸下各看一次。
- 查卡顿：每帧比较 `renderer.info.programs`，新出现的着色器程序连同它的 `cacheKey` 和已有程序逐项对比，
  差在哪一项（环境贴图尺寸、是否双面、灯数）就是没预热到的那一套。

## 游玩日志

`src/telemetry/` 监听游戏事件、收集累计快照并补传。`game.js` 的状态机只接开始/重开，初始化时装配。
`api/telemetry.js` 校验并写入 Neon，`server/telemetry/` 管理数据格式、去重和鉴权。
`api/telemetry-summary.js` 提供受密钥保护的汇总，数据口径与维护见 [telemetry.md](telemetry.md)。
